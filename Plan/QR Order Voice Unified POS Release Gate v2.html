3. Migration ที่จะถูก apply บน staging (ต้องอนุมัติก่อน)

  1. 20260831000001_unified_pos_foundation.sql — flags 3 ตัวบน stores, สถานะ/เวอร์ชันของ item, receipts, voice_aliases
  2. 20260901000001_unified_pos_realtime.sql
  3. 20260901000002_unified_pos_rpc.sql
  4. 20260901000003_unified_pos_fulfillment.sql
  5. 20260901000004_unified_pos_reject.sql
  6. 20260901000005_unified_pos_settlement.sql
  7. 20260902000001_unified_pos_print_intent.sql

ก่อน apply ต้องยืนยัน: รายการ drift จริงของ staging (supabase migration list), backup ล่าสุด, เจ้าของหน้าต่างเวลา และคำสั่งถอย

คุณสมบัติที่ทำให้ถอยได้ปลอดภัย: ทุก flag บน stores default false — schema ขึ้นก่อนได้โดยพฤติกรรมเดิมไม่เปลี่ยน และ "ปิดฟีเจอร์" ทำได้ทันทีโดยไม่ต้องถอย migration

4. ลำดับเปิดใช้งานบน staging (หลังได้อนุมัติ)

  1. apply migration ทั้ง 7 ไฟล์ → ตรวจ schema invariants (flags default false, unique index ของ operation key/print job, RLS ของ voice_aliases)
  2. deploy เว็บขึ้น staging (ยัง ไม่ เปิด flag ใด ๆ) → smoke: /login, /pos ต้องเป็น legacy เหมือนเดิมทุกประการ
  3. เปิด unified_pos_enabled เฉพาะร้านนำร่องที่ระบุชื่อ → UAT ด้วยบัญชีจริง: QR → ครัว → บิล → ชำระ → พิมพ์
  4. เปิด kitchen_queue_enabled แล้ววัด convergence ของบอร์ด (เกณฑ์ ≤2s) และ QR submit (≤1.5s)
  5. เปิด voice_command_enabled เป็นตัวสุดท้าย → เดินตาราง docs/deployment/voice-browser-matrix.md ให้ครบ
  6. ตรวจ multi-store isolation: ร้านที่ไม่ได้เปิด flag ต้องไม่เห็นอะไรเปลี่ยน และไม่มี event ข้ามร้าน
  7. soak ตามหน้าต่างที่เจ้าของอนุมัติ → เจอ Critical/Major = ปิด flag ทันที (ไม่ต้องถอย deploy)

7. รายการที่ยังค้างก่อนเข้า U20 (1.0.0)

  • ค้าง ทดสอบเบราว์เซอร์ด้วยมือตาม docs/deployment/voice-browser-matrix.md (Safari/Firefox/มือถือจริง/screen reader) — ตอนนี้ยืนยันแล้วเฉพาะ Chrome บนมือถือของเจ้าของร้าน
  • บางส่วน performance: อ่านคิวออเดอร์บน production วัดได้ p50 ~137ms (ตัวอย่างจากเครื่องพัฒนา ไม่ใช่เส้นทาง server จริง) — ยังต้องวัด QR submit ≤1.5s และ board ≤2s อย่างเป็นระบบ
  • บางส่วน UAT: ร้านนำร่องใช้งานจริงแล้ว (มีออเดอร์ + บันทึกคำเรียก) แต่ยังไม่ได้เดิน checklist เต็มสาย QR→ครัว→บิล→ชำระ→พิมพ์ พร้อมตรวจ multi-store isolation อย่างเป็นทางการ
  • ค้าง soak window ตามที่เจ้าของอนุมัติ + เกณฑ์ error/performance
  • ค้าง อนุมัติเลขเวอร์ชัน 1.0.0 แล้ว bump package/mobile surfaces + รัน verify ครบก่อน commit

หมายเหตุ: ปัจจุบันอยู่ที่ v0.40.0 บน production โดย flag เปิดเฉพาะ 3 ร้านนำร่อง — การขึ้น 1.0.0 เป็นการ "ประกาศความพร้อม" ไม่ใช่การเปิดใช้เพิ่ม จึงเลื่อนได้จนกว่ารายการข้างบนจะครบ

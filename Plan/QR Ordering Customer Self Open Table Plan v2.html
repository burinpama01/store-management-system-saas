Locked Business Rules (เพิ่มเติม)

ใครเปิดโต๊ะร้านเลือก staff_only หรือ customer_self ที่ store settings
เปิด session เมื่อใด (customer_self)ตอนกดสั่งออเดอร์ "แรก" สำเร็จเท่านั้น — ดูเมนูเฉยๆ ไม่เปิด session
ปุ่มสั่งครั้งแรกแสดงปุ่ม "สั่งและเปิดโต๊ะ" (โปร่งใส บอกลูกค้าว่าจะเปิดโต๊ะ)
ยืนยันออเดอร์แรกระบบยืนยันอัตโนมัติ (auto-confirm) — ไม่มีขั้นตอนพนักงานกดอนุมัติ/ปฏิเสธ; ออเดอร์เข้าบอร์ด QR ตามปกติพร้อมเปิด session
ระยะเวลา session= stores.dine_in_duration_minutes (default 120) ค่าเดียวกับที่พนักงานเปิด
เช็คบิลแล้วนั่งต่อเช็คบิล = เคลียร์ session; กดสั่งใหม่ = เปิด session ใหม่ (idempotent)
session_printedไม่รองรับ customer_self (บังคับ staff_only)
บุฟเฟต์customer_self เปิดได้เฉพาะ session แบบ à la carte (ไม่เลือกแพ็กเกจบุฟเฟต์) — ร้านบุฟเฟต์แนะนำ staff_only
เพลงไม่เปลี่ยน — music eligibility แยกอิสระจาก session เหมือนเดิม

Auto-Session Flow (customer_self)

ลูกค้าสแกน QR (table_bound, customer_self)
  └─ page.tsx: ไม่มี session → โหลดเมนู (เพราะ policy=customer_self) → เข้าแอป
       ปุ่ม CTA = "สั่งและเปิดโต๊ะ"
  └─ ลูกค้าเลือกเมนู กดสั่งออเดอร์แรก
       └─ submitQrOrderAction (service client, re-resolve policy ฝั่ง server)
            ├─ ไม่มี session active และ policy=customer_self และ mode=table_bound
            │    → RPC open_table_session_self(store, table)  [for update lock, idempotent]
            │        ตั้ง current_session_id + session_expires_at = now()+duration
            ├─ มี session active อยู่แล้ว → ใช้ session เดิม (กดพร้อมกัน 2 ครั้งก็ไม่ซ้ำ)
            └─ สร้างออเดอร์ + ระบบยืนยันอัตโนมัติ (ไม่มีขั้นตอนอนุมัติ/ปฏิเสธ)
               → ออเดอร์ขึ้นบอร์ด QR เหมือนออเดอร์ปกติ
  └─ พนักงานเช็คบิล → close_table_session เคลียร์ session
  └─ ลูกค้านั่งต่อ กดสั่งใหม่ → เปิด session ใหม่อัตโนมัติ (วนซ้ำ)

Data Model

Migration warning: ห้าม apply production โดยไม่ขอ approval แยก; local/preview validate ก่อน

-- supabase/migrations/YYYYMMDDHHMMSS_table_open_policy.sql

alter table stores
  add column if not exists table_open_policy text not null default 'staff_only'
    check (table_open_policy in ('staff_only', 'customer_self'));

-- เปิด session โดยลูกค้า: enforce policy ฝั่ง DB + idempotent + audit
create or replace function open_table_session_self(p_store_id uuid, p_table_id uuid)
returns timestamptz
language plpgsql security definer set search_path = public as $$
declare v_minutes int; v_mode text; v_policy text;
        v_expires timestamptz; v_session uuid;
begin
  select dine_in_duration_minutes, qr_ordering_mode, table_open_policy
    into v_minutes, v_mode, v_policy
  from stores where id = p_store_id and is_active;
  if not found then raise exception 'store_unavailable'; end if;
  if v_mode <> 'table_bound' or v_policy <> 'customer_self' then
    raise exception 'self_open_not_allowed';
  end if;

  -- ล็อกแถวโต๊ะกัน race; ถ้ามี session active อยู่แล้วคืนของเดิม
  select session_expires_at into v_expires
  from tables where id = p_table_id and store_id = p_store_id for update;
  if v_expires is not null and v_expires > now() then
    return v_expires;
  end if;

  v_session := gen_random_uuid();
  v_expires := now() + (coalesce(v_minutes,120) || ' minutes')::interval;
  update tables set current_session_id = v_session, session_expires_at = v_expires
    where id = p_table_id and store_id = p_store_id;
  return v_expires;
end $$;

revoke execute on function open_table_session_self(uuid, uuid) from public, anon, authenticated;
-- เรียกผ่าน service client (server action) เท่านั้น

Risks & Open Questions

ตัดสินแล้ว (จากผู้ใช้):

  • ออเดอร์แรก = ระบบ auto-confirm — ไม่เพิ่มขั้นตอนพนักงานอนุมัติ/ปฏิเสธ ออเดอร์ไหลเข้าบอร์ดปกติ (frictionless)
  • ปุ่ม = "สั่งและเปิดโต๊ะ" (แสดงให้ลูกค้ารู้ว่าจะเปิดโต๊ะ)
  • duration = ค่าเดียวกับพนักงานเปิด (dine_in_duration_minutes)
  • notify: ใช้ของเดิมตอนมีออเดอร์ใหม่ ไม่เพิ่ม channel

R1 — Abuse (ยอมรับความเสี่ยง): customer_self ใครสแกน QR โต๊ะก็เปิด session + สั่งได้เอง โดยไม่มีพนักงานคัดกรอง (โมเดล dine-in เชื่อใจ ตามที่ผู้ใช้เลือก). ร้านที่กลัวสั่งป่วนเลือก staff_only ได้. ถ้าต้องการคุมเพิ่มภายหลัง: rate-limit ออเดอร์ต่อโต๊ะ/ต่อช่วงเวลา (follow-up นอก MVP).

R2 — บุฟเฟต์: self-open สร้างได้เฉพาะ session à la carte (ไม่มีการเลือกแพ็กเกจ). ต้องกันไม่ให้ร้านบุฟเฟต์เผลอเปิด customer_self หรือชี้แจงในหน้า settings.

Acceptance Criteria

  • ร้านเลือก table open policy ได้ที่ settings; session_printed บังคับ staff_only
  • customer_self: ลูกค้าดูเมนูได้แม้ยังไม่มี session
  • customer_self: food tab แสดงปุ่ม "สั่งและเปิดโต๊ะ" เมื่อยังไม่มี session
  • customer_self: กดสั่งออเดอร์แรก → session เปิดอัตโนมัติ (duration = ค่าร้าน) + ออเดอร์ถูกบันทึกและ ยืนยันโดยระบบทันที (ไม่มีขั้นตอนอนุมัติ/ปฏิเสธ)
  • เช็คบิลแล้วกดสั่งใหม่ → เปิด session ใหม่ได้
  • กดสั่งซ้อนกัน/สองคนพร้อมกัน → ได้ session เดียว (idempotent, ไม่ซ้อน)
  • staff_only ทำงานเหมือนเดิมทุกประการ (ไม่ regress)
  • policy ถูก enforce ทั้งที่ server action และ RPC (กันปลอม client)
  • tests/typecheck/lint ผ่าน

3. ADR ที่ต้องรักษา

ADR-001

AI ไม่แตะ DB โดยตรง — เรียกเฉพาะ StoreOS tools

ADR-002

Tool layer provider-agnostic — ไม่ import OpenAI types ใน business tools

ADR-003

Voice และ Text ใช้ Tool Dispatcher เดียวกัน

ADR-004

AI permission เป็น gate เพิ่ม ไม่แทน domain permission (pos.use ฯลฯ)

ADR-005

MVP = Push-to-Talk เท่านั้น

ADR-006

Model ส่ง semantic query — StoreOS resolve ID

ADR-007

Critical / policy fail = fail closed

ADR-008 (ใหม่)

Coexistence: Voice POS / Standby / AI Assistant ไม่รวม module ใน MVP; แชร์ domain services เท่านั้น

ADR-009 (ใหม่)

Product/cart resolution ต้องผ่าน Voice POS resolver path ที่เดียว

ADR-010 (ใหม่)

Entitlement ผ่าน billing canUseFeature — ห้าม parallel flag ระบบใหม่

4. ADR-008 — Voice coexistence (บังคับก่อน Live)

ต้องมีเอกสารสั้น docs/ai-assistant/VOICE_COEXISTENCE.md ก่อนเปิดไมค์ AI Assistant ใน pilot
ระบบบทบาทช่วง pilotUI entry
Voice POS (เดิม)Primary สำหรับ intent→cart ที่ร้านใช้แล้วคงปุ่ม/flow เดิม
Windows Voice Standby / Launcher TTSOptional input/output channel — ไม่ผูก AI Assistant MVPคงตามแผน Standby แยก
AI Assistant (ใหม่)Opt-in overlay บน POS; text ก่อน แล้วค่อย PTTปุ่ม AI แยก ไม่แทนปุ่ม Voice POS
  • ห้ามให้คำสั่งเดียวกันวิ่งสอง pipeline พร้อมกัน
  • ถ้าเปิด AI Assistant mic → mute/ignore Voice POS capture ใน session นั้น (และกลับกัน)
  • ผลลัพธ์ cart ต้องมาจาก domain service เดียว — ไม่มี cart state คนละชุด
  • หลัง pilot ค่อยตัดสินใจ absorb หรือ sunset ช่องทางใดช่องทางหนึ่ง

8. Feature gating & permissions

Capabilities ที่ map เข้า entitlement (ชื่อสุดท้ายจาก audit):

ai_assistant.enabled
ai_assistant.voice
ai_assistant.text
ai_assistant.pos_tools

Permissions เพิ่มได้ แต่ tool ยังต้องผ่าน domain permission จริง เช่น pos.add_item ต้อง ai_assistant.use AND ai_assistant.pos AND pos.use

Kill switches (env + platform)

AI_ASSISTANT_ENABLED
AI_ASSISTANT_LIVE_ENABLED
AI_ASSISTANT_MUTATIONS_ENABLED

Default production: code deploy ได้ แต่ org/store entitlement = false จนกว่าเปิด pilot

9. Device / terminal binding

อย่า block ทั้งฟีเจอร์ ถ้ายังไม่มี device registry สมบูรณ์
  1. Phase 0 ตอบ: มี device_id / terminal_id source of truth หรือยัง
  2. ถ้ามี — ผูก AI session กับ terminal + active cart
  3. ถ้ายังไม่มี — MVP รับ activeCartId / activeOrderId จาก UI แล้ว server validate ว่าอยู่ใน store + user scope
  4. ห้าม query “ออเดอร์ล่าสุดของร้าน” เป็น fallback

10. Confirmation & critical policy

  • ห้ามเชื่อ confirmed: true จากโมเดล
  • server confirmation record + arguments_hash + expiry
  • MVP: block refund / void closed bill / cash drawer adjust / permission / price change
  • PIN/reauth ใช้ได้ต่อเมื่อมี flow จริงใน repo — อย่า mock แล้วปล่อย critical

11. OpenAI Live — verify ก่อน implement

Phase 6 เริ่มด้วย spike เอกสาร + PoC เล็ก ห้ามเขียน production WebRTC ทั้งก้อนก่อนผ่านเกตนี้

Preferred

Browser (audio + limited events)
  ↔ OpenAI Live
      → sideband/delegation tool request
      → StoreOS trusted server → Tool Dispatcher

Fallback ถ้า sideband/delegation ไม่พร้อมกับ model ที่เลือก

Browser → StoreOS /api/ai-assistant/tools/execute
  ต้องมี: assistantSessionId + signed session token (HMAC/short-TTL)
  + tool allowlist ที่ bind ตอนสร้าง session
  ห้าม generic execute ไร้ session / ห้าม client เลือก tool list เอง
  OPENAI_API_KEY อยู่ server เท่านั้น

Hard caps ตั้งแต่ Live PR แรก (ไม่รอ billing phase)

  • max live session minutes (config; เริ่ม ~10–15 สำหรับ pilot)
  • max tool calls / session
  • max concurrent live sessions / store
  • AI_ASSISTANT_LIVE_ENABLED kill switch
  • meter: audio seconds + session seconds + tool_calls (แม้ยังไม่คิดเงิน)

Latency: แยก speech / model / tool / DB / TTS — เป้า <2.5s เป็น aspiration ไม่ใช่ ship gate จนกว่าวัดจาก pilot จริง

15. Definition of Done — MVP

  • เปิด/ปิดรายร้านผ่าน entitlement จริง
  • text command POS ทำงาน end-to-end
  • push-to-talk ใช้ Tool Dispatcher เดียวกับ text
  • shared resolver — ไม่มี catalog path คนละชุด
  • current order ถูก terminal/session
  • ambiguity ถามกลับ · duplicate tool ไม่ทำซ้ำ · undo ได้
  • audit ทุก mutation · usage ถูกบันทึก
  • API key ไม่อยู่ client · critical ยัง block
  • AI outage ≠ POS outage · Voice POS coexistence ชัด
  • lint / typecheck / unit / integration / e2e critical path ผ่าน

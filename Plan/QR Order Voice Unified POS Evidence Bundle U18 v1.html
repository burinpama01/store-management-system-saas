3. Security review (ทำในรอบนี้)

หัวข้อสิ่งที่ตรวจผล / การจัดการ
RLS ของผิวใหม่ voice_aliases: อ่าน = สมาชิกร้าน, เขียน/ลบ = manager+ ; server action ทั้งสองตัวผ่าน requirePermission("settings.manage_store") และใช้ user client (ไม่ใช่ service client) ผ่าน — แก้เพิ่ม: toggle alias ผูก store_id ของ context ด้วย (เดิมอ้าง id อย่างเดียว พึ่ง RLS ชั้นเดียว)
เงิน/พิมพ์ซ้ำ settlement ใช้ operation key + request hash (replay คืนผลเดิม), print job unique ต่อ source key, client ไม่ auto-print ตอน replay ผ่าน — คุมด้วย integration 7 เคส + e2e replay/print
เสียงแตะเงินไม่ได้ parser block Tier D (ชำระ/เช็คบิล/ส่วนลด/คืนเงิน/ยกเลิก/ล้างตะกร้า) ก่อนทุก pattern; executor ตะกร้าเป็น local ล้วน ไม่มี server action; ตะกร้าล็อกหลังสร้างออร์เดอร์ ผ่าน — คุมด้วย matrix 30 วลี + e2e blocked payment
Voice privacy สแกน migration + source จริง: ไม่มีคอลัมน์เก็บเสียง/คำพูด, ไม่มี localStorage/console/network ในเส้นทางเสียง, telemetry ประกอบใหม่จาก allowlist + purge 30 วัน ผ่าน — voice-pos-privacy.test.ts 10 เคส
ความลับใน log gate มี secret scan ของ evidence (ผลลัพธ์ clean); โค้ดรอบนี้ไม่ log token/คีย์/transcript ผ่าน
alias ไม่เรียนรู้เอง ไม่มีเส้นทางใดเขียน alias จากคำพูด — repository รับเฉพาะข้อความจากฟอร์ม, มี created_by + is_active ไว้ตรวจย้อนหลัง ผ่าน

4. บั๊กที่พบและแก้ระหว่างการตรวจ (ไม่ใช่ของที่วางแผนไว้)

  1. hydration mismatch (React #418) ที่ปุ่มเสียง — ตัดสิน isSupported() ตอน render แรก ทำให้ server (ไม่มี window) กับ client ได้ข้อความคนละแบบ พบจากเกณฑ์ "console zero errors" ของ U17 → แก้เป็น useSyncExternalStore (server snapshot = null, ปุ่มปิดไว้ก่อน)
  2. database.types.ts ปิดบล็อก Tables เร็วเกินไป — unified_pos_operation_receipts และ voice_aliases หลุดออกจาก type map (query แล้วได้ never) → ย้ายวงเล็บปิดไปท้ายรายการตาราง
  3. seed ขาด receipt_settings ทำให้ integration printing ล้มหลัง reset (รายละเอียดในหัวข้อ 1)
  4. lint: ref ตอน render / setState ใน effect (รายละเอียดในหัวข้อ 1)

5. ข้อจำกัดที่รับไว้อย่างรู้ตัว (accepted risk)

เรื่องสถานะเจ้าของ / เส้นตายทางถอย
/pos ไม่มี Ctrl+K palette (อยู่นอก layout (dashboard)) — ข้อความ fallback ในหน้า POS จึงชี้ไปที่แท็บบนหน้าจอแทน รับไว้ เจ้าของผลิตภัณฑ์ · ทบทวนใน U19 ไม่กระทบการทำงาน — ผู้ใช้ยังกดปุ่ม/แท็บได้ทุกกรณี
คำสั่งเสียง "ค้นหา" จะโฟกัสได้เมื่อหน้ามี [data-voice-focus="search"] เท่านั้น (หน้าขายปัจจุบันมีแต่ cart) รับไว้ เจ้าของผลิตภัณฑ์ · เมื่อหน้าขายใหม่มีช่องค้นหา ระบบตอบว่า "หน้านี้ยังไม่มีช่องค้นหา" ไม่มี error
ตารางเบราว์เซอร์ (Safari/Firefox/มือถือจริง) ยังไม่ได้ทดสอบด้วยมือ ค้าง ผู้ทดสอบ · ต้องเสร็จใน U19 docs/deployment/voice-browser-matrix.md — ปิด flag เสียงต่อร้านได้ทันที
telemetry เสียงยังอยู่ในหน่วยความจำของ session (ยังไม่ส่งขึ้น server) ตั้งใจ — ถ้าจะส่งขึ้น server ต้องผ่าน sanitizeVoiceTelemetry เท่านั้น

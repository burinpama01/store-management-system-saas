เสียงพูดแจ้งเตือน (TTS) + ให้ POS/Launcher เห็นออเดอร์เดลิเวอรี

แผน v1 · 2026-09-07 · ฐาน v0.46.3

1. ปัญหาที่พบจากการอ่านโค้ดจริง

1.1 Launcher ไม่รองรับเดลิเวอรี

  • Launcher เป็นเปลือก WebView2 ที่เปิด https://www.store-os.online/pos ตายตัว (windows/StoreOS.Launcher/Configuration/LauncherSettings.cs:22) ไม่มีโค้ดเกี่ยวกับเดลิเวอรีเลย และสาย native↔web มีแค่คำปลุกเสียง (windows/StoreOS.Voice/StandbyContract.cs)
  • ตัวเด้งออเดอร์ทั้ง 3 ตัว (DeliveryGlobalNotifier / QrOrderGlobalNotifier / NotificationGlobalNotifier) mount อยู่ใน src/app/(dashboard)/layout.tsx:199-212 เท่านั้น
  • /pos อยู่นอก route group (dashboard) และไม่มี layout ของตัวเอง → เครื่องที่รัน Launcher ไม่มีทางรู้ว่ามีออเดอร์เดลิเวอรี/QR เข้า จนกว่าจะออกจาก POS
  • ออเดอร์เดลิเวอรีไม่ผ่าน dispatcher (NotificationType ไม่มีชนิดเดลิเวอรี) — รู้ได้ทางเดียวคือ poll /api/connect/pending ทุก 12 วินาที ซึ่งอยู่ใน DeliveryGlobalNotifier

1.2 เสียงแจ้งเตือนไม่บอกว่าเกิดอะไร

ทุกเสียงเป็น beep จาก oscillator (src/shared/notifications/alert-sound.ts:48) — แยกได้แค่ qr (สูง 3 จังหวะ) กับ connect (ต่ำ 2 จังหวะ) พนักงานต้องมองจอถึงจะรู้เรื่อง

2. ขอบเขตที่เคาะแล้ว

  1. ทำทั้งสองอย่าง: ย้ายตัวเด้งลง /pos ด้วย + เปลี่ยนเสียงเป็น TTS
  2. กลไกเสียง: speechSynthesis (th-TH) และถอยเป็น beep เดิมเมื่อเครื่องไม่มีเสียงไทย
  3. ตั้งค่า 2 ชั้น: ร้านตั้งค่าเริ่มต้น (คอลัมน์ใน stores) + แต่ละเครื่องปรับทับได้ (localStorage)

3. สิ่งที่จะสร้าง/แก้

ไฟล์สถานะสาระ
supabase/migrations/20260907000000_notification_voice_announcement.sql DB stores.notification_voice_enabled boolean not null default false — default false เพื่อให้ deploy แล้วไม่มีร้านไหนพูดขึ้นมาเองโดยไม่ได้ขอ
src/shared/notifications/announce.ts ใหม่ เลือกเสียงไทยจาก getVoices() (รอ voiceschanged), speakAnnouncement() คืน false เมื่อพูดไม่ได้, อ่าน/เขียนค่าตั้งต่อเครื่อง (storeos.notify.voice = store | on | off)
src/shared/notifications/alert-sound.ts แก้ useRepeatingAlert(active, pattern, announcement?) — พูดครั้งเดียวตอนขึ้น dialog รอบซ้ำทุก 3.5 วิ เป็น beep เหมือนเดิม; พูดไม่ได้ = beep ทันที
src/shared/notifications/StoreAlertNotifiers.tsx ใหม่ server component รวมการโหลด kitchen station / receipt settings / printers แล้ว render 3 notifier — ตัดโค้ดซ้ำระหว่าง dashboard กับ POS
src/app/(dashboard)/layout.tsx แก้ เรียก StoreAlertNotifiers แทนการประกอบเอง (พฤติกรรมเดิมทุกอย่าง)
src/app/pos/page.tsx แก้ render StoreAlertNotifiers คู่กับ POS shell ทั้ง legacy และ unified
Notifier ทั้ง 3 แก้ ส่งข้อความพูด: "ออเดอร์เดลิเวอรีเข้าใหม่" / "ออเดอร์โต๊ะ 4 เข้าใหม่" / ตามชนิดแจ้งเตือน
src/app/(dashboard)/settings/notifications/* แก้ สวิตช์ระดับร้าน + ปุ่ม "ทดสอบเสียงพูด" (ต้องกดบนเครื่องร้านจริงเพื่อพิสูจน์ว่า WebView2 มีเสียงไทย)
src/app/(dashboard)/settings/devices/* แก้ ตัวเลือกต่อเครื่อง: ตามร้าน / เปิด / ปิด
tests/unit/notification-voice-announcement.test.ts ใหม่ เลือกเสียงไทย, ถอยเป็น beep, ลำดับความสำคัญของค่าตั้ง 2 ชั้น, ข้อความที่ประกาศ

4. จุดที่พลาดง่าย (บันทึกไว้ก่อนลงมือ)

ห้ามทำเป็น src/app/pos/layout.tsx — layout จะครอบ /pos/display ซึ่งเป็นจอที่หันหาลูกค้า ถ้าเด้ง dialog ออเดอร์ที่นั่นคือเอาข้อมูลร้านไปโชว์ลูกค้า จึงต้อง mount ที่ page.tsx ของ /pos เท่านั้น
เสียงเตือนดังซ้ำทุก 3.5 วินาที — ถ้าพูดทุกรอบจะทับกันจนฟังไม่รู้เรื่อง (synth.cancel() ตัดของเก่าทิ้ง) จึงพูดครั้งแรกครั้งเดียว
Chromium เลือกเสียงเองเมื่อไม่มี th-TH แล้วจะอ่านไทยด้วยเสียงอังกฤษเป็นเสียงต่างดาว — ต้องเช็ค getVoices() ก่อนพูดเสมอ ไม่มีก็ beep
getVoices() คืน array ว่างในครั้งแรกบน Chromium ต้องรอ event voiceschanged
POS กินเต็มจอ (h-dvh overflow-hidden) — notifier ต้องเป็น overlay fixed เท่านั้น ห้ามแทรกใน flow

5. ลำดับงาน

  1. migration + ต่อสายคอลัมน์เข้า Store type / repository
  2. announce.ts + แก้ alert-sound.ts + unit tests
  3. StoreAlertNotifiers.tsx แล้วให้ dashboard layout ใช้ (ต้องไม่เปลี่ยนพฤติกรรมเดิม)
  4. ต่อเข้า /pos ทั้ง legacy และ unified
  5. ข้อความพูดในแต่ละ notifier
  6. หน้าตั้งค่า 2 ชั้น + ปุ่มทดสอบเสียง
  7. npm run typecheck + npm test + npm run lint
  8. บันทึก log ลง Obsidian

6. เกณฑ์ว่าเสร็จ

  • เปิด /pos แล้วมีออเดอร์เดลิเวอรีเข้า → เด้ง dialog + ได้ยินเสียงบนเครื่องที่รัน Launcher
  • เปิดสวิตช์ระดับร้าน → ได้ยินประโยคไทยแทน beep; ปิดที่เครื่องใดเครื่องหนึ่ง → เครื่องนั้นกลับไป beep
  • เครื่องที่ไม่มีเสียงไทย → ยังได้ยิน beep เดิม ไม่เงียบและไม่อ่านผิดภาษา
  • typecheck / test / lint ผ่านหมด

ยังไม่ครอบคลุมในรอบนี้: /pos/grocery (POS ขายส่ง), การพูดผ่าน native TTS ของ Launcher, และการแจ้งเตือนเดลิเวอรีผ่าน LINE/Telegram/Push (ต้องเพิ่ม NotificationType ใหม่ = งานคนละก้อน)

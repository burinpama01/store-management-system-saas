1. สร้างแอปใน Play Console คุณ

  1. เข้า play.google.com/console → All apps → Create app
  2. App name: StoreOS · Default language: ไทย · App or game: App · Free/Paid: Free
  3. ติ๊กยอมรับ Developer Program Policies + US export laws → Create app

2. Play App Signing (ปล่อยให้ Google ถือ signing key) คุณ

เมื่ออัปโหลด AAB ครั้งแรก Play จะเปิด Play App Signing อัตโนมัติ: Google ถือ "app signing key" ให้ ส่วน storeos-upload.jks ของเราเป็น "upload key" (ใช้เซ็นตอนอัปโหลดเท่านั้น) — นี่คือค่าเริ่มต้นและปลอดภัยที่สุด ไม่ต้องตั้งอะไรเพิ่ม

3. กรอก App content (บังคับก่อน release ทุก track) คุณ

เมนูซ้าย → Policy → App content ต้องกรอกให้ครบทุกหัวข้อ ไม่งั้นปล่อย release ไม่ได้แม้แต่ internal:

หัวข้อกรอกอย่างไร
Privacy policyวาง https://store-os-manage.vercel.app/privacy-policy
Adsแอปนี้ ไม่มีโฆษณา → No
App accessต้องล็อกอิน → เลือก "All or some functionality is restricted" แล้วให้ บัญชีทดสอบ (อีเมล/รหัสร้านตัวอย่าง) เพื่อให้ทีมรีวิว Google เข้าใช้ได้ — จำเป็น ไม่งั้นถูกปฏิเสธ
Content ratingทำแบบสอบถาม → ประเภท Business/Productivity → ได้เรต "ทุกวัย"
Target audienceอายุ 18+ (แอปธุรกิจ) — ไม่ใช่แอปสำหรับเด็ก
Data safetyดูตาราง §4 ด้านล่าง (สำคัญ — ต้องตรงกับที่แอปเก็บจริง)
Government apps / Financial featuresไม่ใช่แอปรัฐ; มีรับชำระเงินร้านค้า → ตอบตามจริง (ไม่ใช่ผู้ให้บริการการเงิน)

4. Data safety form (ให้ตรงกับที่แอปเก็บจริง) คุณ

ข้อมูลเก็บ?วัตถุประสงค์แชร์ให้ภายนอก?
Location (โดยประมาณ/แม่นยำ)ใช่ยืนยันพื้นที่ลงเวลาเข้า-ออกงาน (App functionality)ไม่
Personal info (อีเมล/ชื่อ)ใช่บัญชีผู้ใช้ + จัดการร้านไม่ขาย; ส่งผู้ให้บริการ (Supabase/Vercel) เท่าที่จำเป็น
App activity / ออร์เดอร์ใช่ทำงานหลักของระบบ POSไม่
ข้อมูลการชำระเงินใช่ประมวลผลการขายผู้ประมวลผลชำระเงินเท่าที่จำเป็น

หมายเหตุ: Bluetooth (เครื่องพิมพ์) และ Notifications ไม่ใช่ "ข้อมูลส่วนบุคคล" — ไม่ต้องประกาศใน data safety แต่จะเห็นใน permission ของ APK; ถ้า Google ถามให้ตอบว่าใช้ต่อเครื่องพิมพ์ + แจ้งเตือนออร์เดอร์

5. อัปโหลด AAB เข้า Internal testing คุณ

  1. เมนูซ้าย → Test and release → Testing → Internal testing → Create new release
  2. ลาก/อัปโหลดไฟล์ app-release.aab (จาก path ด้านบน)
  3. Release name ปล่อยตามค่าเริ่มต้น (1 (1.0)); ใส่ release notes สั้น ๆ เช่น "รุ่นทดสอบภายในรุ่นแรก"
  4. Next → Save → Review release → Start rollout to Internal testing
  5. แท็บ Testers: สร้าง email list ใส่อีเมลผู้ทดสอบ (ของคุณ) → คัดลอก "Copy link" ให้ผู้ทดสอบเปิดในมือถือเพื่อ opt-in แล้วติดตั้งผ่าน Play
Internal testing เผยแพร่ทันที (ไม่ต้องรอ Google review) — ทดสอบติดตั้งจาก Play ได้เลยภายในไม่กี่นาที เหมาะยืนยันว่า AAB ทำงานก่อนส่ง production

6. เลื่อนขึ้น Production (ส่ง Google review) คุณ

  1. ต้องกรอก Main store listing ให้ครบก่อน: ชื่อ, คำอธิบายสั้น (80 ตัว), คำอธิบายเต็ม, ไอคอน 512×512, feature graphic 1024×500, ภาพหน้าจอ อย่างน้อย 2 รูป (โทรศัพท์)
  2. Production → Create new release → เลื่อน AAB จาก internal มาใช้ (promote) หรืออัปโหลดใหม่
  3. Start rollout → Google review ปกติ 1-7 วัน

7. ความเสี่ยงที่ควรรู้

ประเด็นรับมือ
Google อาจถามว่าแอปเป็น "web wrapper"แอปมีฟีเจอร์ native จริง (push, Bluetooth printing, GPS) — ระบุในหมายเหตุ; ปกติผ่านสำหรับแอปธุรกิจที่มี native function
App access (บัญชีทดสอบ)ต้องให้บัญชีตัวอย่างที่ล็อกอินได้ ไม่งั้นรีวิวเข้าไม่ถึงเนื้อหา = ปฏิเสธ
Data safety ไม่ตรงกับ permissionประกาศ location ให้ตรง (แอปขอ ACCESS_FINE/COARSE_LOCATION)

8. ต่อไป: iOS

iOS build บนเครื่อง Windows ไม่ได้ — เมื่อพร้อมทำ iOS ให้ตั้ง Codemagic + Apple App Store Connect API key แล้วผมเขียน codemagic.yaml ให้ build .ipa → TestFlight (คนละ runbook)

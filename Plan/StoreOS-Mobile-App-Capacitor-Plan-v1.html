📱 StoreOS Mobile App — Capacitor Plan v1

วันที่: 2026-07-04 · โปรเจกต์: Store management system saas (StoreOS) · สถานะ: รออนุมัติ Phase 0

1. โจทย์และปัญหาที่ต้องแก้

ทำไมเว็บอย่างเดียวไม่พอ
  • เครื่องปริ้นบน iOS ต่อไม่ได้: ระบบพิมพ์ปัจจุบัน (print-router.ts) ใช้ Web Bluetooth → Web USB → PDF ซึ่ง iOS Safari ไม่รองรับ Web Bluetooth และ WebUSB เลย ผู้ใช้ iPhone/iPad จึงพิมพ์ตรงไม่ได้ (ทางอ้อมเดียวคือ Print Hub agent บนเครื่อง Windows)
  • Push notification ไม่มี: ปัจจุบันแจ้งเตือนผ่าน LINE/Telegram เท่านั้น (notifications/dispatcher.ts) ไม่มี web push/service worker; iOS web push ก็จำกัดมาก (ต้อง Add to Home Screen + iOS 16.4+ และไม่เสถียร)

2. ทางเลือกที่พิจารณา

ทางเลือกPushปริ้น iOSแรงงานสรุป
A) Capacitor wrapper แนะนำ
ห่อเว็บ StoreOS เดิมใน native shell (WKWebView) + native plugin		 ✅ APNs/FCM เต็มรูปแบบ ✅ BLE native + TCP 9100 ต่ำ — โค้ดเว็บเดิมใช้ได้ ~100% codebase เดียว, ทุกฟีเจอร์อัปเดตตามเว็บอัตโนมัติ
B) Flutter แอปแยก
เขียน POS ใหม่ (ทีมมีประสบการณ์จาก JDC)		 ✅ ✅ สูงมาก — ต้อง rebuild POS/UI ทั้งหมด เก็บไว้เป็น long-term option; ไม่คุ้มสำหรับโจทย์นี้
C) PWA
Add to Home Screen + web push		 ⚠️ จำกัด/ไม่เสถียรบน iOS ❌ ไม่มีทางต่อ BLE บน iOS ต่ำสุด ตกรอบ — แก้โจทย์เครื่องปริ้นไม่ได้

3. สถาปัตยกรรม (ทางเลือก A)

┌─ StoreOS App (iOS/Android) ─────────────────────────┐
│  Capacitor Shell                                     │
│  ├─ WKWebView → โหลด https://store-os-manage.vercel.app │
│  ├─ @capacitor/push-notifications → APNs / FCM       │
│  └─ Printer plugin (BLE ESC/POS + TCP:9100)          │
│        ↑ window.Capacitor bridge                     │
└──────────┼───────────────────────────────────────────┘
           │ reuse bytes จาก buildReceiptPrinterBytes()
           ▼
   print-router.ts เพิ่ม channel "native"
   (native BLE → native TCP → เดิม: BT → USB → PDF)
  • เว็บเดิมคือแอป: shell โหลด URL production — deploy เว็บ = แอปได้ฟีเจอร์ใหม่ทันที ไม่ต้องส่ง App Store review ทุกครั้ง (Apple อนุญาตเพราะเป็น web content ไม่ใช่ native binary)
  • Push: เพิ่ม channel "push" ใน dispatcher.ts (โครงสร้าง fan-out ต่อ channel รองรับอยู่แล้ว) + ตาราง device_push_tokens (user_id, org_id, platform, token) + ส่งผ่าน FCM HTTP v1 (FCM ครอบ APNs ให้ — จัดการ iOS/Android ที่เดียว)
  • ปริ้น: ใน print-router.ts เช็ค Capacitor.isNativePlatform() → ส่ง bytes ESC/POS raster เดิม (ภาษาไทยพิมพ์ได้เพราะ render เป็นบิตแมปอยู่แล้ว) ไปยัง plugin BLE หรือ TCP 9100 — ไม่ต้องแก้ logic ใบเสร็จเลย
  • Session/Login: Supabase auth cookie ทำงานใน WKWebView ปกติ; ต้องทดสอบ persistence + deep link storeos://

4. แผนงานแบ่งเฟส

Phase 0 เตรียมความพร้อม (0.5 วัน + รอ Apple อนุมัติ 1-2 วัน)

  • สมัคร Apple Developer Program ($99/ปี) — ต้องทำก่อนทุกอย่าง
  • สร้างโปรเจกต์ Firebase (ใช้ FCM อย่างเดียว ฟรี) + อัปโหลด APNs key
  • เลือก build pipeline สำหรับ iOS (เครื่อง dev เป็น Windows → build iOS บนเครื่องตัวเองไม่ได้): แนะนำ Codemagic (ฟรี 500 นาที/เดือน, รองรับ Capacitor) หรือ GitHub Actions macOS runner

Phase 1 Capacitor shell + Android ก่อน (1-2 วัน)

  • เพิ่ม capacitor.config.ts (server.url → prod) ในโฟลเดอร์แยก mobile/ ใน repo เดิม
  • ไอคอน/splash จากโลโก้ StoreOS, ทดสอบ login + POS + QR flow ใน WebView บน Android จริง (ทดสอบบน Windows ได้)
  • จัดการ external link (สลิป, PDF ใบเสร็จ) ให้เปิดถูกที่

Phase 2 Push Notification (2-3 วัน)

  • Migration: ตาราง device_push_tokens + RLS
  • หน้าเว็บฝั่ง client: ถ้า Capacitor.isNativePlatform() → ขอ permission + ลงทะเบียน token ผูกกับ user/org
  • เพิ่ม channel push ใน NOTIFICATION_CHANNELS + ส่งผ่าน FCM HTTP v1 ใน dispatcher (ยิงตอน: ออเดอร์ QR ใหม่, เรียกพนักงาน, ออเดอร์ Connect เข้า, กะเงินสด ฯลฯ — ใช้จุด notifyOwnerSafely เดิม)
  • ตั้งค่าเปิด/ปิดราย notification type ใน Settings (โครง notification_settings เดิมรองรับ channel อยู่แล้ว)

Phase 3 Printer bridge iOS/Android (2-3 วัน + ทดสอบ HW)

  • ติดตั้ง plugin thermal printer (BLE) + plugin TCP socket สำหรับเครื่องพิมพ์ LAN port 9100
  • print-router.ts: เพิ่ม channel native-bluetooth / native-network นำหน้า fallback เดิม
  • UI จับคู่เครื่องพิมพ์ในแอป (scan BLE, จำ device ต่อ store)
  • ทดสอบกับ PT-280 จริง (งานค้างเดิมเรื่องทดสอบ HW จะได้ปิดพร้อมกัน)

Phase 4 iOS build + TestFlight (1-2 วัน)

  • ตั้ง Codemagic: certificate/provisioning อัตโนมัติ → build .ipa → TestFlight
  • ทดสอบบน iPhone/iPad จริง: push + BLE print + POS flow

Phase 5 เผยแพร่ (1 วัน + review 1-7 วัน)

  • App Store + Google Play listing (ภาพหน้าจอ, privacy policy — ต้องมีหน้า privacy บนเว็บ)
  • เพิ่มปุ่ม "ดาวน์โหลดแอป" บน landing/แดชบอร์ด

5. ความเสี่ยงและการรับมือ

ความเสี่ยงระดับการรับมือ
App Store Guideline 4.2 Apple อาจปฏิเสธแอปที่เป็น "แค่เว็บห่อ" กลาง แอปเรามีฟีเจอร์ native จริง (push + Bluetooth printing) ซึ่งเป็นเหตุผลหลักของแอป; ระบุใน review notes ให้ชัด; ถ้ายังติด → เพิ่ม native tab bar/offline splash
Build iOS บน Windows ไม่ได้ แน่นอน ใช้ Codemagic/GitHub Actions macOS runner ตั้งแต่ Phase 0 — ไม่ต้องซื้อ Mac
Plugin BLE กับ PT-280 เข้ากันไม่ได้ กลาง bytes ESC/POS raster เดิมพิสูจน์แล้วว่าใช้ได้ เหลือแค่ transport; มี fallback TCP 9100 + Print Hub เดิม
Session หลุดใน WKWebView ต่ำ Supabase ใช้ cookie/localStorage ปกติ; ทดสอบใน Phase 1 ก่อนลงทุนต่อ

แผนงาน: ตรวจจับ + เชื่อมต่อเครื่องพิมพ์ USB อัตโนมัติผ่าน Print Hub

เวอร์ชัน 1 · 2026-09-03 · StoreOS (Store management system SaaS)

1. โจทย์

เจ้าของร้านมีเครื่องพิมพ์ความร้อนแบบ WiFi (บอร์ด WIFI Printer V1.0.08_2.0.6R, โหมด APSTA, IP 192.168.1.59) แต่เวลาไปใช้งานหน้าร้านอยากใช้ สาย USB ต่อตรงเข้าเครื่องคอม/โน้ตบุ๊ก Windows โดย ไม่ต้องตั้งค่า WiFi ใหม่ทุกครั้ง ที่ย้ายร้าน/เปลี่ยนเราเตอร์ และอยากให้ระบบ ตรวจจับเครื่องพิมพ์เองแล้วเชื่อมต่ออัตโนมัติ

อุปกรณ์หน้าเคาน์เตอร์: คอม/โน้ตบุ๊ก Windows · แนวทางที่เลือก: Print Hub + USB auto-detect

ช่องว่าง/บั๊กที่พบระหว่างสำรวจ

  1. ensureUsbConnected() (usb-client.ts:86) คืน false ทันทีถ้าไม่มีชื่อที่จำไว้ และจับคู่อุปกรณ์ด้วย productName — เครื่องพิมพ์ราคาถูกหลายรุ่นคืนชื่อว่าง/ซ้ำ → รีเฟรชหน้าแล้วต่อไม่ติด ตกไป PDF เงียบ ๆ
  2. ไม่มี listener navigator.usb "connect"/"disconnect" → เสียบสายหลังเปิดหน้าแล้วระบบไม่รู้
  3. ข้อจำกัดหลักของ WebUSB บน Windows: ถ้าเครื่องพิมพ์ถูกติดตั้งเป็น printer ของ Windows ไดรเวอร์ usbprint.sys จะยึดอุปกรณ์ → claimInterface ขึ้น “Access denied” แก้ได้เฉพาะทาง Print Hub หรือเปลี่ยนไดรเวอร์ด้วย Zadig (ไม่เหมาะกับร้านค้า)

→ ข้อ 3 คือเหตุผลที่เลือกเส้นทาง Print Hub เพราะพิมพ์ผ่าน Windows Spooler แบบ RAW ได้เลย ไม่ต้องยุ่งกับไดรเวอร์ และแท็บเล็ต/iPad ในร้านก็ยิงงานเข้าเครื่องพิมพ์ตัวเดียวกันได้ด้วย

🖨️ เครื่องพิมพ์ USB

Agent เดิม long-poll อยู่แล้ว เพิ่มแค่ target_kind = 'usb' อีกชนิด และเพิ่มความสามารถ “สแกนเครื่องพิมพ์ที่เสียบอยู่แล้วรายงานกลับเซิร์ฟเวอร์”

ทำไมต้อง Windows Spooler RAW (winspool P/Invoke)

  • copy /b file \\.\USB001 — ไม่เสถียร ต้องแชร์เครื่องพิมพ์ก่อน
  • Out-Printer — เป็น text/GDI ไม่ใช่ raw ESC/POS → ภาษาไทย + raster เพี้ยน
  • OpenPrinter → StartDocPrinter(datatype "RAW") → WritePrinter — ส่งไบต์ ESC/POS ดิบตรงถึงเครื่องพิมพ์ ผ่าน PowerShell Add-Type ใช้ได้กับทุกเครื่องพิมพ์ที่ Windows มองเห็น (USB / แชร์ / IP) ไม่ต้องเปลี่ยนไดรเวอร์ ← เลือกทางนี้

ระบบ render ใบเสร็จเป็น raster bitmap อยู่แล้ว (escpos-raster.ts, GS v 0) ภาษาไทยจึงออกเหมือนกันทุกช่องทางโดยไม่ต้องแตะ code page

อัลกอริทึมตรวจจับอัตโนมัติ

Get-CimInstance Win32_Printer → { Name, PortName, Default, WorkOffline }
เรียงลำดับความน่าจะเป็น:
  1. ชื่อที่ร้านตั้งค่าไว้ (hub_usb_name) ถ้ายังเสียบอยู่          → ใช้ตัวนั้น
  2. PortName ขึ้นต้น USB* + ชื่อเข้าข่ายเครื่องพิมพ์ใบเสร็จ
     (POS / Thermal / Receipt / 58 / 80 / XP- / TM- / EPSON / RP / PT-)
  3. PortName ขึ้นต้น USB* ตัวใดก็ได้
  4. เครื่องพิมพ์ default ของ Windows
  ไม่พบเลย → job ล้มเหลวพร้อมข้อความไทยที่บอกวิธีแก้

ผลการสแกนถูกส่งกลับพร้อมทุก poll → เก็บที่ stores.print_hub_devices → หน้า /settings/print-hub แสดงรายการให้กดเลือก “ใช้เครื่องนี้” ได้ในคลิกเดียว

4. ขอบเขตงาน

Phase 1 — ฐานข้อมูล

migration ใหม่ supabase/migrations/20260904100000_print_hub_usb.sql

  • print_jobs.target_kind — ขยาย check เป็น ('ip','bt','usb')
  • printers.hub_usb_name text — ชื่อเครื่องพิมพ์ Windows (ว่าง = ให้ตรวจจับเอง)
  • stores.print_hub_devices jsonb + print_hub_devices_at timestamptz — ผลสแกนล่าสุดจาก agent

Phase 2 — เซิร์ฟเวอร์

ไฟล์สิ่งที่แก้
modules/printing/print-hub.tsเพิ่ม validateHubUsbPrinterName() — กันอักขระอันตราย (quote/backtick/$/control char) ก่อนส่งเข้า PowerShell, ยาวไม่เกิน 128
print-hub-repository.tsPrintTargetKind += "usb"; เพิ่ม saveHubDevices() / getHubDevices()
api/print/enqueue/route.tsสาขาใหม่ printer.type === "usb" → enqueue kind usb, device = ชื่อที่ตั้งไว้ หรือ null = auto
api/print/hub/poll/route.tsรับ devices[] จาก agent → บันทึกลง store
api/print/hub/status/route.tsคืน devices ให้หน้า settings แสดงผลแบบ live
unified-pos/print-intent.tstoHubRoutableTarget() รองรับ printer type usb (auto-print หลังชำระเงินใช้เส้นทางนี้)
stores/types.ts + repository.ts + database.types.tsฟิลด์ hubUsbName

Phase 3 — Agent (scripts/print-hub.mjs)

  • listWindowsPrinters() — PowerShell + ConvertTo-Json, cache 30 วินาที
  • pickUsbPrinter(printers, requestedName) — อัลกอริทึมข้อ 3 (ฟังก์ชันบริสุทธิ์ → unit test ได้)
  • sendToWindowsPrinter(name, bytes) — Add-Type winspool P/Invoke ส่ง RAW
  • runPollCycle() — รองรับ job.kind === "usb" + แนบ devices ไปกับ poll ทุกครั้ง
  • อัปเดต scripts/build-print-hub-zip.mjs / print-hub.cmd ถ้าจำเป็น

Phase 4 — เส้นทางพิมพ์ฝั่ง client

  • receipt-printer.ts → isHubReceiptPrinter() รวมเครื่องพิมพ์ type usb ที่ผูก Hub ไว้
  • printReceiptWithFallback() — เครื่องพิมพ์ USB-ผ่าน-Hub ส่งเข้าคิวแทนการเรียก WebUSB adapter (ซึ่งจะพังบน Windows ที่ไดรเวอร์ยึดอุปกรณ์)
  • ลำดับ fallback เดิม (BLE → Web Bluetooth → WebUSB → PDF) คงไว้ครบสำหรับร้านที่ไม่ได้ลง Hub

Phase 5 — UI

  • /settings/print-hub — การ์ดใหม่ “เครื่องพิมพ์ที่ตรวจพบบนพีซีแคชเชียร์” แสดงชื่อ + พอร์ต + สถานะออนไลน์ พร้อมปุ่ม ใช้เครื่องนี้ (บันทึกเป็น printer type usb) และ ทดสอบพิมพ์
  • ตัวเลือก “ตรวจจับอัตโนมัติ (แนะนำ)” — ไม่ผูกชื่อ ย้ายเครื่อง/เปลี่ยนพอร์ตแล้วยังพิมพ์ได้
  • อัปเดตไดอะแกรมเส้นทางงานพิมพ์ให้มี USB

Phase 6 — Logging (กฎ AGENTS.md: ทุกฟีเจอร์ใหม่ต้องมี log)

  • บันทึก system_event_logs ทั้งเส้นทางสำเร็จและล้มเหลว: ตรวจพบเครื่องพิมพ์ใหม่, เลือก target อัตโนมัติได้ตัวไหน, พิมพ์สำเร็จ/ล้มเหลวพร้อมเหตุผล, Hub ไม่พบเครื่องพิมพ์ USB เลย

5. ความเสี่ยง / ข้อควรระวัง

ความเสี่ยงการรับมือ
Command injection ผ่านชื่อเครื่องพิมพ์ (ส่งเข้า PowerShell)validate ฝั่ง server + normalize ซ้ำฝั่ง agent + escape ' → '' เหมือนที่ทำกับ COM port
ผู้ใช้ยังไม่ได้ติดตั้งไดรเวอร์เครื่องพิมพ์บน Windows → ไม่ขึ้นใน Win32_PrinterUI บอกวิธี: เสียบ USB → Windows ติดตั้ง “USB Printing Support”/ไดรเวอร์ผู้ผลิต → กดสแกนใหม่ (ปุ่ม refresh)
เครื่องพิมพ์ WiFi ตัวนี้อาจ enumerate เป็น USB-serial (CH340) แทน printer classรายการที่ agent ส่งกลับจะรวม COM port ด้วย → ผู้ใช้เลือกเป็น target แบบ COM ได้ (เส้นทาง bt เดิมรองรับอยู่แล้ว)
เครื่องพิมพ์ raster ใหญ่ค้างที่ spoolerยังคง cap MAX_PRINT_JOB_BYTES 256 KB และ ack ผลจริงกลับ (สำเร็จ/พัง) ไม่รายงานสำเร็จหลอก
Hub ออฟไลน์ → งานค้างคิวเงียบใช้กลไก hubOnline เดิมที่แจ้งเตือนผู้ใช้อยู่แล้ว

6. เกณฑ์ตรวจรับ

  1. เสียบสาย USB เครื่องพิมพ์เข้าพีซีแคชเชียร์ที่มี Print Hub → หน้า /settings/print-hub แสดงชื่อเครื่องพิมพ์ภายใน ~3 วินาที โดยไม่ต้องตั้งค่าอะไร
  2. กด “ใช้เครื่องนี้” + ทดสอบพิมพ์ → ใบเสร็จภาษาไทยออกถูกต้อง
  3. ชำระเงินที่ POS → ใบเสร็จออกอัตโนมัติโดยไม่มี dialog ใด ๆ
  4. ถอดสาย → เสียบใหม่ (คนละพอร์ต USB) → ยังพิมพ์ได้โดยไม่ต้องตั้งค่าซ้ำ
  5. สั่งพิมพ์จากแท็บเล็ต/iPad ในร้าน → ออกที่เครื่องพิมพ์ USB ตัวเดียวกัน
  6. npm test + npm run typecheck ผ่านทั้งหมด (รวม unit test ใหม่ของ pickUsbPrinter และ validator)

7. สิ่งที่ยัง “ต้องทดสอบด้วยฮาร์ดแวร์จริง”

การส่ง RAW ผ่าน winspool และการ enumerate เครื่องพิมพ์ ทดสอบอัตโนมัติได้เฉพาะระดับ unit (ฟังก์ชันบริสุทธิ์ + mock runner) ส่วน การพิมพ์ออกกระดาษจริง ต้องทดสอบที่หน้าร้านกับเครื่องพิมพ์ตัวจริง — จะระบุไว้ในรายงานปิดงานอย่างชัดเจน ไม่รายงานว่าผ่านถ้ายังไม่ได้ยิงจริง

Recommended Phasing

1

Dedicated Grocery POS + Barcode

เริ่มจาก POS ร้านของชำแยกต่างหากที่ /pos/grocery. ใช้ POS เดิมเป็น reference/service base แต่ไม่แก้ PosTerminal.tsx ให้กลายเป็น multi-mode component.

  • เพิ่ม route ใหม่ src/app/pos/grocery/page.tsx.
  • เพิ่ม UI ใหม่ GroceryPosTerminal.tsx สำหรับ scan-first flow.
  • เพิ่ม product/variant barcode contract และ lookup by barcode/SKU.
  • เพิ่ม scanner buffer สำหรับ keyboard wedge scanner, duplicate-scan quantity และ not-found workflow.
2

Coupon + Loyalty Points

ต่อจาก cart/order contract ที่ชัดแล้ว เพื่อไม่ให้ discount กับ point ledger ขัดกัน.

  • เพิ่ม customer profile และ membership lookup.
  • เพิ่ม coupon policy engine ฝั่ง server.
  • เพิ่ม loyalty ledger earn/redeem/reversal.
  • ผูก receipt และ order history.
3

WiFi Printer + Dual Screen

ยกระดับหน้าร้าน: พิมพ์ใบเสร็จผ่าน WiFi แบบปลอดภัย และเปิดจอลูกค้าแยกจาก POS operator.

  • ใช้ printer config จากฐานข้อมูลเท่านั้น.
  • เพิ่ม printer health test และ retry status.
  • เพิ่ม customer display route/session.
  • รองรับ second window และ external monitor.
4

Offline-First + Enterprise

ทำหลัง order/coupon/loyalty/printer contract นิ่ง เพราะ phase นี้แตะ transaction, sync และ reporting ข้ามสาขา.

  • IndexedDB operation queue + sync state.
  • Idempotency key ต่อ order/payment/redemption.
  • Conflict/replay policy ฝั่ง server.
  • Enterprise branch dashboard/reporting.

Target Architecture

Catalog

  • barcode ที่ product และ variant.
  • sku ยังใช้ได้ แต่ไม่แทน barcode.
  • unique ต่อ store_id สำหรับ barcode ที่ active.
  • รองรับ grocery unit: ชิ้น, แพ็ค, กล่อง, กิโลกรัม ใน phase ถัดไปถ้าต้องชั่งน้ำหนัก.

Dedicated Grocery POS

  • สร้าง bounded context ใหม่ที่ src/modules/grocery-pos.
  • สร้าง route ใหม่ src/app/pos/grocery และ component GroceryPosTerminal.tsx.
  • reuse cart/order/payment/printing service เดิมผ่าน adapter ที่เล็กและ test ได้.
  • ห้ามยัด scanner state หรือ grocery shortcuts เข้า PosTerminal.tsx.

Promotion

  • coupon validation ฝั่ง server เท่านั้น.
  • policy: date, min spend, customer, store, usage limit.
  • ระบุ stacking rule กับ manual discount.
  • redemption ต้อง reverse ได้เมื่อ void order.

Loyalty

  • ledger เป็น append-only.
  • earn point หลัง payment success เท่านั้น.
  • redeem point เป็น discount source แยกจาก coupon.
  • void/refund ต้องสร้าง reversal entry.

Offline Sync

  • IndexedDB queue เก็บ draft operation.
  • service worker สำหรับ app shell/cache.
  • sync endpoint ตรวจ idempotency และ catalog version.
  • UI ต้องแสดง pending/synced/failed ชัดเจน.

Risks / Stop Conditions

POS Boundary

ห้ามเปลี่ยน src/app/pos/PosTerminal.tsx ให้รองรับ grocery mode แบบรวมทุกอย่างในไฟล์เดียว. ถ้าต้องใช้ logic เดิม ให้ extract/shared service แบบมี tests ก่อน.

Production / DB

ห้าม apply remote migration, production deploy, printer hardware claim หรือ DB write UAT โดยไม่มี approval แยก พร้อม target/backup/rollback.

Offline Sync

ถ้าไม่มี idempotency และ conflict policy ที่ชัด ห้ามเปิด offline full sync ให้ร้านจริง เพราะเสี่ยง order/payment/stock ซ้ำ.

Printer Security

IP printer ต้องพิมพ์เฉพาะ host/port ที่บันทึกใน store printer config และผ่าน permission/package gate เท่านั้น.

SaaS Platform Page Expansion Plan v1

แผนเพิ่มหน้าที่ขาดของ Store Management SaaS หลังนิยาม role ใหม่: super_admin เป็นผู้ดูแล platform/tenant/billing, owner เป็นผู้ลงทะเบียนเช่าซื้อระบบ, และ admin/manager/cashier/staff เป็นทีมในร้านที่ owner สร้างเท่านั้น

Date: 2026-06-05 Status: Proposed Source: repo routes + Obsidian current + Graphify report Do not overwrite: Super Admin Platform Roadmap v1

1. Role Model ที่ต้องล็อกก่อนสร้างหน้า

super_admin

Platform Operator

  • จัดการ tenant/organization/store ทั้งระบบ
  • จัดการ SaaS billing, plan, subscription status, invoice/support case
  • ตั้งค่า tenant ระดับ platform เช่น feature override, suspension, quota, owner reset
  • ดู audit/security events ข้าม tenant แบบ read/operate ตามสิทธิ
  • ไม่ใช่คนขายหน้าร้าน และไม่ควรถูกพาเข้า POS/dashboard ร้านเป็น default
owner

Tenant Buyer

  • เป็นคนลงทะเบียน ซื้อ/เช่าระบบ และสร้าง organization/store แรก
  • จัดการ billing portal ของ tenant ตัวเอง
  • สร้าง admin/manager/cashier/staff ให้ร้านตัวเองเท่านั้น
  • จัดการ store settings, receipt, notifications, users, permissions ภายใน tenant
tenant staff

admin / manager / cashier / staff

  • ถูกสร้างหรือเชิญโดย owner/admin ที่มีสิทธิ
  • ไม่มี public signup เอง
  • ไม่เห็น platform console
  • ทุก action ต้องถูกจำกัดด้วย organization/store boundary และ permission overrides

Decision สำคัญ: public registration ต้องสร้าง owner เท่านั้น; super_admin ต้องมาจาก controlled bootstrap/platform process เท่านั้น

3. Information Architecture ที่แนะนำ

public site

Public / Marketing

  • /: landing page ของระบบ
  • /pricing: plan comparison
  • /register: owner signup
  • /login, /reset-password: auth เดิม
tenant app

Owner + Store Team

  • /onboarding: owner setup หลังสมัคร
  • /, /catalog, /pos, /reports: tenant operations เดิม
  • /settings/billing: owner billing
  • /settings/team: owner/admin สร้าง staff
platform console

Super Admin

  • /system: platform overview
  • /system/tenants: tenant management
  • /system/billing: SaaS billing ops
  • /system/settings: plan/feature defaults
  • /system/audit: platform audit
routing rule

Post-login Redirect

  • super_admin → /system
  • owner → / tenant dashboard หรือ /onboarding ถ้ายัง setup ไม่ครบ
  • admin/manager/cashier/staff → first allowed tenant route
  • ถ้า user มีหลาย store ให้ใช้ store switcher เดิม แต่ไม่ใช้กับ platform-only task

4. Phase Roadmap

Phase 1
Public + Owner Entry

สร้างทางเข้า SaaS ที่ถูกต้อง

  • ทำ landing page ของระบบพร้อม CTA สมัครใช้งาน
  • ทำ pricing page อิง package gates ที่มีจริงใน code
  • ทำ owner registration flow: Auth user + organization + store + owner membership
  • ทำ onboarding checklist สำหรับ owner หลังสมัคร

Success: คนเช่าระบบสมัครเองได้และกลายเป็น owner เท่านั้น; staff ไม่มี self-signup

Phase 2
Super Admin Shell

แยก platform console ออกจาก tenant app

  • เพิ่ม /system layout/nav เฉพาะ super_admin
  • เพิ่ม tenant list/search/status surface
  • เพิ่ม tenant detail แบบ read-first: owner, stores, subscription, feature locks, recent audit
  • ปรับ post-login redirect ของ super_admin ไป platform console

Success: super_admin ไม่ถูก default เข้า POS/store dashboard และไม่ต้องมี current store เพื่อจัดการ platform

Phase 3
Billing Operations

ปิด flow SaaS billing ทั้งสองฝั่ง

  • Owner billing page: checkout/customer portal/current plan/history
  • Super admin billing page: subscription state, webhook status, failed payment, manual plan override พร้อม reason
  • เพิ่ม audit log สำหรับ plan override, suspend, reactivate
  • เพิ่ม tests สำหรับ tenant boundary และ Stripe webhook idempotency ที่เกี่ยวข้อง
Phase 4
Tenant Controls

ทำเครื่องมือจัดการ tenant แบบปลอดภัย

  • Tenant settings จาก super_admin: feature override, quota, suspension, owner reset
  • Read-only impersonation preview หรือ support mode ต้องมี explicit reason + audit; ไม่ใช้ silent impersonation
  • Export audit/security report ตาม tenant
  • เพิ่ม support diagnostics ที่ไม่แสดง secret/token
Phase 5
Hardening

ทำให้พร้อมขายจริง

  • Authenticated browser QA สำหรับ owner signup, super_admin console, billing, tenant staff invite
  • RLS integration tests สำหรับ super_admin/platform scope และ tenant scope
  • Rate limit / abuse guard สำหรับ register/reset/invite
  • Production readiness checklist ก่อน deploy

5. Data / Permission Changes ที่ต้องวางก่อนลงมือ

Database / Auth

  • ยืนยัน schema สำหรับ organization/store creation ตอน owner signup
  • เพิ่ม onboarding status ต่อ organization/store ถ้ายังไม่มี
  • เพิ่ม platform audit table หรือขยาย audit log เดิมให้รองรับ platform action
  • แยก platform actions ออกจาก tenant store actions ให้ชัด

Permission / Guard

  • เพิ่ม helper เช่น requirePlatformPermission() หรือ getPlatformContext()
  • ทบทวนว่า super_admin ควรมี tenant operation permissions โดย default หรือควรเป็น support/elevated mode
  • Owner-only invite: owner/admin ที่ได้รับสิทธิเท่านั้นสร้าง tenant staff ได้
  • ทุก mutation ต้องมี audit และ tenant boundary

6. Acceptance Criteria

  • Public visitor เห็น landing/pricing/register โดยไม่ต้อง login
  • Owner signup สร้าง owner + tenant + store แรกได้แบบ atomic/fail closed
  • super_admin เข้า /system ได้และไม่ถูกบังคับเลือก store สำหรับ platform tasks
  • owner จัดการ billing ของ tenant ตัวเองได้ แต่ไม่เห็น platform billing ของ tenant อื่น
  • admin/manager/cashier/staff ไม่สามารถสมัครเอง, ไม่เห็น /system, และไม่สร้าง role ที่สูงกว่า policy
  • ทุก page/action มี unit/source guard และอย่างน้อยหนึ่ง authenticated browser smoke ใน phase ที่เกี่ยวข้อง
  • Obsidian log/current/decision ต้อง sync หลังแต่ละ phase

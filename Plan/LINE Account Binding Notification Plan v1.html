LINE Account Binding Notification Implementation Plan

แผนนี้สร้าง flow ให้ผู้สมัครใช้บริการเห็น dialog หลังสมัครสำเร็จเพื่อ Add LINE แล้วไปหน้า /settings/notifications?lineLink=1 สำหรับผูก LINE ก่อนรับแจ้งเตือนส่วนตัว โดยใช้ LINE Messaging API, webhook signature verification, และ server-only token เท่านั้น

For agentic workers: REQUIRED SUB-SKILL: ใช้ superpowers:subagent-driven-development หรือ superpowers:executing-plans ตอน implement แผนนี้ทีละ task. ทุก task ต้องทำแบบ TDD: เขียน RED test, verify fail, implement, verify pass.

Goal

ผู้สมัครสมัครเสร็จแล้วเห็น dialog Add LINE และสามารถผูก LINE account ผ่านหน้า settings เพื่อรับ notification แบบ one-to-one ได้โดยไม่เปิดเผย token ฝั่ง client.

Architecture

ใช้ LINE Official Account + Messaging API. Webhook รับ message, follow, และ accountLink; backend สร้าง secure nonce แล้วผูก line_user_id กับ user/organization หลัง LINE ส่งผล account link กลับมา.

Safety

ห้ามใช้ LINE Notify เดิม, ห้าม hard-code secret, ห้ามส่ง token ไป browser, ห้าม deploy production หรือ apply migration remote โดยไม่มี approval.

User Flow

1

สมัครสำเร็จ

registerOwner สร้าง tenant/store/user แล้ว redirect พร้อม flag สำหรับเปิด dialog.

2

Dialog Add LINE

หน้า onboarding/register success แสดง dialog มีปุ่ม Add LINE และปุ่มไปตั้งค่าแจ้งเตือน.

3

Settings Link

/settings/notifications?lineLink=1 แสดง LINE binding panel พร้อมสถานะผูกแล้ว/ยังไม่ผูก.

4

LINE Webhook

ผู้ใช้ add OA แล้วส่งข้อความ ผูกบัญชี; webhook issue link token และ reply secure link.

5

รับแจ้งเตือน

เมื่อ accountLink สำเร็จ ระบบเก็บ line_user_id และใช้ push message เฉพาะ server-side.

Data Model

Proposed migration shape

ใช้ table แยกเพื่อป้องกันปนกับ Telegram target และรองรับ unlink/audit ได้ชัด.

create table if not exists line_account_links (
  id uuid primary key default gen_random_uuid(),
  organization_id uuid not null references organizations(id) on delete cascade,
  app_user_id uuid not null references auth.users(id) on delete cascade,
  line_user_id text not null,
  status text not null default 'linked' check (status in ('linked', 'unlinked')),
  linked_at timestamptz not null default now(),
  unlinked_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (organization_id, app_user_id),
  unique (line_user_id)
);

create table if not exists line_account_link_sessions (
  id uuid primary key default gen_random_uuid(),
  organization_id uuid not null references organizations(id) on delete cascade,
  app_user_id uuid not null references auth.users(id) on delete cascade,
  nonce_hash text not null unique,
  expires_at timestamptz not null,
  consumed_at timestamptz,
  created_at timestamptz not null default now()
);

RLS: owner/member ใน organization อ่านสถานะของตัวเองได้, write ผ่าน server action/service role เท่านั้น, accountLink webhook ใช้ service role เพื่อ consume nonce หลัง verify signature แล้ว.

Security Checklist

  • ทุก webhook request ต้อง verify x-line-signature จาก raw body ก่อน parse trust.
  • Nonce ต้อง random, hash, expire, และ single-use.
  • ห้าม log LINE_CHANNEL_ACCESS_TOKEN, LINE_CHANNEL_SECRET, nonce raw, link token, หรือ provider response ที่มีข้อมูล sensitive.
  • RLS ต้องกัน cross-tenant read/write; service role ใช้เฉพาะ webhook/server action ที่จำเป็น.
  • ผู้ใช้หนึ่งคนใน organization มี LINE link ได้หนึ่งรายการ; LINE user ID เดียวไม่ควรถูก bind ซ้ำข้าม account โดยไม่ unlink ก่อน.
  • Notification failure ต้องไม่ทำให้ signup/order/service request transaction fail.

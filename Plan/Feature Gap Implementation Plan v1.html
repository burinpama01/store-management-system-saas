สำหรับ agent ที่จะ implement: ใช้ workflow Scope → Route → Implement → Review → Fix → Verify → Document. หลัง package ที่แตะ code/config ต้อง spawn code_reviewer; ถ้าได้ผล review ครบแล้วให้ cleanup/kill sub-agent ทันที.

Task Q1: Stock & Stock Alert

Success criteria: staff แจ้งของหมดได้, manager/admin เห็นและปิดรายการได้, POS/QR ห้ามขายเกิน stock, stock ลดเมื่อ order paid/accepted ตาม flow ที่กำหนด.

  • เขียน failing tests ใน tests/unit/stock.test.ts: create alert requires store/user, resolve alert requires role, stock decrement rejects negative quantity.
  • เพิ่ม migration สำหรับ stock_alerts และ audit fields: organization_id, store_id, requested_by_user_id, items jsonb, status, resolved_by_user_id, resolved_at.
  • เพิ่ม src/modules/stock/repository.ts พร้อม store boundary ทุก query และ RLS-friendly filters.
  • เพิ่มหน้า /stock ใน dashboard พร้อม form แจ้งของหมดและ list สถานะ.
  • แก้ POS/QR action ให้ verify track_stock และ stock_quantity จาก DB ไม่เชื่อข้อมูล client.
  • เพิ่ม stock decrement หลัง payment close ใน POS และหลัง QR order accepted ถ้าเลือก policy แบบ accept-time decrement.
  • เพิ่ม navigation link เฉพาะ role ที่มี stock.manage หรือ staff ที่ส่ง alert ได้.

Review & Verification Gate

GateRequired ActionDone Criteria
TDD เริ่มแต่ละ package ด้วย failing unit test หรือ regression test เห็น fail ก่อน implement และ pass หลัง fix
Security ทุก server action ต้องใช้ requirePermission(), store/org boundary, input validation ไม่มี client-trusted price/store/user/role
Code Review spawn code_reviewer หลังแต่ละ package ไม่มี Critical/Major open; cleanup sub-agent หลังได้ผลครบ
Full Verification รัน targeted tests, npm run typecheck, npm run lint, และ npm test ก่อนสรุป pass หรือระบุ blocker ชัดเจน
Docs อัปเดต Obsidian log.md, current.md, และ issue files ถ้ามี bug มี learning review และ next step ล่าสุด

PromptPay Billing Migration Plan v1

เปลี่ยนระบบเก็บเงิน SaaS subscription จาก Stripe → PromptPay (EMVCo payload หรือ QR image ที่ super admin ตั้งค่า) + ตรวจสลิปอัตโนมัติด้วย slip2go + รอบใช้งานแบบ 30 วัน / 1 ปี เมื่อหมดอายุใช้ระบบไม่ได้ เน้นตลาดไทย

Decisions (จากผู้ใช้)

Pricing: default ของผม ปรับได้ภายหลัง slip2go: SLIP2GO_API_KEY อยู่ใน .env.local แล้ว Stripe: ปิดไว้ ไม่ลบ code ตลาดไทยก่อน

2. Data model (migration ใหม่)

platform_settings (singleton)

  • promptpay_id (เบอร์/เลขบัตร, nullable), promptpay_name, promptpay_qr_image_path (storage path สำหรับบัญชีที่ไม่มี PromptPay)
  • billing_provider default 'promptpay' (รองรับสลับกลับ stripe ภายหลัง), updated_by, updated_at

payment_submissions

  • organization_id, plan, duration (30d/1y), amount_expected
  • slip_ref (unique — กันใช้สลิปซ้ำ), verified_amount, slip2go_raw (jsonb), slip_image_path
  • status (pending|verified|rejected|duplicate), reason, submitted_by, created_at, verified_at

subscriptions (ใช้ของเดิม)

  • ใช้ plan, status, current_period_end; verified payment → set plan, status=active, current_period_end = now + duration
  • เพิ่ม status expired ใน check constraint; เข้าถึงได้เมื่อ active และ current_period_end > now

RLS: payment_submissions อ่าน/เขียนเฉพาะ member ของ org (มี billing.manage); platform_settings เขียนเฉพาะ super_admin, อ่านได้ผ่าน service path

3. Modules

  • billing/pricing.ts — DURATION_PRICES + getPrice(tier,duration) (pure, tested)
  • billing/promptpay-provider.ts — สร้าง EMVCo payload (reuse printing/promptpay-qr.ts) ใส่ amount; หรือคืน static QR image url จาก platform_settings
  • billing/slip2go.ts — adapter เรียก {SLIP2GO_BASE_URL}/api/verify-slip/qr-code/info (Bearer SLIP2GO_API_KEY), fail-closed ถ้าไม่มี key; parseSlip2goResponse() pure + defensive (tested)
  • billing/subscription-service.ts — submitPayment(): verify ผ่าน slip2go → ตรวจ amount ≥ expected + receiver ตรง promptpay + ref ไม่ซ้ำ → extend subscription + audit log
  • billing/platform-settings.ts — get/set platform PromptPay config (service client)

4. Flow

  1. Owner → /settings/billing เลือก tier + duration (30วัน/1ปี)
  2. ระบบแสดง PromptPay QR (EMVCo amount-embedded จาก promptpay_id หรือ static image) + ยอดที่ต้องโอน
  3. ลูกค้าโอน → อัปโหลดสลิป (image) หรือวาง QR payload จากสลิป
  4. server action → slip2go verify → ตรวจ amount/receiver/ref-dedup
  5. ผ่าน → subscription.current_period_end = now + duration, status=active, plan=tier; เขียน audit
  6. ไม่ผ่าน → status rejected/duplicate + เหตุผล

5. Enforcement (หมดอายุ = ใช้ไม่ได้)

  • getOptionalResolvedCurrentPermissions: ถ้า subscription หมดอายุ (current_period_end < now) และไม่ใช่ super_admin → redirect /settings/billing (ต่ออายุ) ยกเว้นหน้า billing เอง
  • รวม guard เดียวกับ tenant suspension ที่มีอยู่

6. ปิด Stripe (ไม่ลบ code)

  • billing_provider='promptpay' → route /api/stripe/* return 404 (early guard), เก็บไฟล์ + dependency ไว้
  • billing UI เปลี่ยนจากปุ่ม Stripe → PromptPay flow
  • Stripe tests เดิมคงไว้ (unit ของ util ยังผ่าน)

7. Super admin config

  • หน้า /system/settings: ตั้ง promptpay_id + ชื่อ หรืออัปโหลด QR image (สำหรับบัญชีที่ไม่มี PromptPay), เลือก billing_provider
  • เขียนผ่าน server action ที่ requireSystemAccess() + audit log

8. Verification

  • unit: pricing, parseSlip2goResponse, amount/receiver/dedup logic, promptpay payload amount
  • build + typecheck + lint
  • live (มี key): ทดสอบ slip2go ด้วยสลิปจริง + ปรับ field mapping; apply migration ผ่าน db push (มี approval)
  • bump version, commit, Obsidian log

หมายเหตุ: base URL/field ของ slip2go อาจต้องปรับหลังเห็น response จริง — ออกแบบ adapter ให้ config ได้

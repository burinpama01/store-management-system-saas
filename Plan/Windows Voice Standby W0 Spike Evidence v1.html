Windows Voice Standby
W0 Spike Evidence v1

เอกสารนี้บันทึกผลการวัดจริงของ Task 9 (W0 spike) ตาม “Windows Voice Standby and Print Hub Implementation Plan v3” — วัดเท่าที่วัดได้บนเครื่องพัฒนา และระบุอย่างชัดเจนว่าอะไรยังปิดไม่ได้เพราะขาดเครื่อง/ฮาร์ดแวร์/ข้อมูลหน้าร้าน
วันที่วัด 6 กันยายน 2026 · ไม่มีการสร้างฟีเจอร์ production ในรอบนี้

สรุปหนึ่งย่อหน้า

เงื่อนไขข้อแรกของ W0 คือ “เครื่องต้องมีชุดรู้จำเสียงที่ใช้ได้จริง” — ผ่านบนเครื่องพัฒนา 1 เครื่อง (มี recognizer en-US + WebView2 152.0.4191.62) แต่แผนกำหนดให้เก็บอย่างน้อย 3 เครื่องในตลาดไทย จึงยัง ปิด gate ไม่ได้ ส่วนข้ออื่นของ W0 (mic handoff 100 รอบ, false wake, CPU, device-busy, user-activation) ต้องใช้ไมโครโฟนจริงและ native wake host ซึ่งยังไม่มีในรีโป จึงยังวัดไม่ได้ และตาม Rollout Order ของแผน v3 นั้น Phase 6 (Voice W0) จะเริ่มได้ก็ต่อเมื่อ Print Hub ผ่าน pilot 21 วันก่อน ซึ่งยังไม่เริ่มนับ

สถานะ Task 9 = ยังไม่เริ่มได้ตามกติกาของแผนเอง — entry gate (Phase 5 pilot) ยังไม่ผ่าน คำแนะนำ: คง push-to-talk ต่อไป และอย่าเพิ่งลงแรงกับ W1–W12

เช็กลิสต์ W0 ตามแผน v3 Task 9

เกณฑ์สถานะเหตุผล / สิ่งที่ต้องมี
inventory recognizer บนเครื่องไทยอย่างน้อย 3 รุ่น 1 / 3 เก็บได้เฉพาะเครื่องพัฒนา (Windows 11 Home SL build 26200) ต้องรัน probe เดิมบนเครื่อง POS หน้าร้านอีกอย่างน้อย 2 รุ่น
mic handoff 100 รอบกับ VoiceCommandButton วัดไม่ได้ ต้องมี native wake host ที่ปล่อยไมค์แล้วรอ AudioState=Stopped ก่อนส่ง wake.detected — ยังไม่มีในรีโป (Launcher ปัจจุบันไม่มีโค้ด standby เลย) และต้องมีไมโครโฟนจริง
contract command.sessionStarted / sessionExtended / sessionEnded ยังไม่ทำ เป็นสัญญาสำหรับ harness ของ spike ไม่ควรเขียนลง production ก่อน entry gate ผ่าน
watchdog > maximum web listening window + fallback push-to-talk ยังไม่ทำ ต้องวัดค่า listening window จริงก่อน — เกี่ยวโยงกับข้อมูลเดิมที่วัดได้ 1.8–3.8 วินาที (timeout จริงตั้ง 6 วินาที)
false wake / CPU / device-busy / user-activation วัดไม่ได้ ต้องมี wake engine ทำงานจริงในสภาพเสียงร้าน 65–75 dBA ตามเกณฑ์แผน v1
business case: เหตุการณ์ “มือไม่ว่าง” ต่อกะ จากร้านนำร่อง 3 ร้าน ไม่มีข้อมูล Voice AI Phase 1 ปิด flag อยู่ทุกร้าน จึงยังไม่มีการใช้งานจริงให้เก็บสถิติ

Entry gate ที่ยังไม่ผ่าน (สำคัญกว่าตัว spike)

คำแนะนำ

1. คง push-to-talk เป็นทางเดียวไปก่อน — ตรงกับเงื่อนไขในแผนเองที่ว่า “ถ้าไม่ผ่านให้คง push-to-talk”
2. งานที่ให้ผลจริงกว่าคือเปิด Phase 5 — เอา Print Hub + Launcher ไปติดตั้งบนเครื่องร้านจริง 1 เครื่อง แล้วเริ่มนับ 21 วัน พร้อมกับเปิด flag voice_ai_fallback_enabled ให้ร้านนำร่อง เพื่อให้มีข้อมูล business case ของ W0 ไปด้วยในตัว
3. เมื่อไปหน้าร้าน ให้รัน probe เดิมทุกเครื่อง powershell -ExecutionPolicy Bypass -File scripts\windows-voice\install-en-us-recognizer.ps1 (แบบ Administrator เพื่อให้อ่าน capability ได้) แล้วเก็บ JSON ลง artifacts/voice-standby-w0/ ครบ 3 เครื่องจึงจะปิดเกณฑ์ข้อแรกได้

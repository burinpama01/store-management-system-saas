21 กันยายน 2026 · สถานะ: กำลังดำเนินการตามคำสั่งเริ่มเลย

ขอบเขตที่อนุมัติ

ใช้ Beam Charges client และ credential codec เดิม เพิ่มบัญชีรับเงินแพลตฟอร์มที่ /system/settings พร้อม Slip2Go สำรอง ใช้ QR ล็อกยอด ยืนยันผ่าน server lookup และ signed webhook ไม่แตะบัญชี Beam ของร้าน ไม่ deploy หรือ migrate production

1. ข้อมูลและความปลอดภัย

เพิ่ม config ใน platform_settings โดยไม่ส่ง secret ไป client เพิ่ม platform_billing_orders ที่ service role เท่านั้นเข้าถึงได้ เก็บราคา ส่วนลด ธุรกิจ ผู้รับ และ credential snapshot ของรายการ ใช้ RPC ยืนยันรายการ ล็อกองค์กรและรายการ บันทึก payment_submissions และต่ออายุใน transaction เดียว เก็บผล test แยกโดยไม่ให้สิทธิ์จริง

2. Backend

สร้าง beam-settings.ts สำหรับ config และ beam-billing.ts สำหรับการสร้าง ตรวจสถานะ และตรวจสลิป ใช้ idempotency key เท่ากับ order id บันทึกก่อนเรียก Beam เมื่อผลไม่แน่ชัดห้ามสร้างรายการใหม่หรือสลับช่องทาง จนตรวจผลเดิมได้ Fallback ใช้ได้ก่อนสร้าง Beam หรือเมื่อยืนยัน FAILED เท่านั้น ตรวจยอด ผู้รับ วันเวลา และสลิปซ้ำ

3. UI

เพิ่ม BeamBillingSettings.tsx แสดง Merchant ID แบบปิดบัง ช่องรหัสว่างเพื่อคงเดิม environment และ fallback เพิ่ม BeamPackagePayment.tsx ใน billing แสดง QR ยอด แพ็กเกจ สถานะ และปุ่มตรวจอีกครั้ง ปิดการเปลี่ยนช่องทางเมื่อยังมีรายการค้าง ใช้ CSS token ของระบบเดิม

4. ทดสอบและ review

เขียน tests/unit/beam-platform-billing.test.ts ให้ล้มเหลวก่อน implementation ทดสอบยอดผิด reference ผิด pending test environment receiver/time mismatch ตรวจ RPC ด้วย PostgreSQL ใน transaction rollback รวมกรณี duplicate และสิทธิ์ anon/authenticated รัน Vitest ชุด billing/Beam, TypeScript, ESLint และ reviewer เฉพาะ diff แก้ finding แล้วทดสอบซ้ำ

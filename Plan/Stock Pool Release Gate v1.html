Maintenance impact

Migration จับ table locks เพื่อ cutover ที่ปลอดภัย จึงต้องหยุด writes ชั่วคราวและทำ backup ก่อน apply ห้ามเปิดรับ POS/QR write ระหว่าง migration ชุดนี้

STOP conditions
  • remote history เปลี่ยน หรือพบว่า 20260803000001 เคย apply แล้ว
  • migration ใด fail, invariant ไม่ผ่าน, เกิด negative/cross-store/unlinked tracked Variant
  • build/deployment ไม่ READY หรือ smoke พบ 5xx/data mismatch

Production checklist

  1. ยืนยัน environment เป็น production และทำ database backup/snapshot ที่กู้คืนได้
  2. เปิด maintenance/write quiescence สำหรับ POS, QR และ Stock
  3. ตรวจ remote migration list ซ้ำ แล้ว dry-run/apply 00001–00005 ตามลำดับ
  4. ตรวจ invariant: tracked Variant มีหนึ่ง link, Pool ไม่ติดลบ, ไม่มี cross-store/org link, movement equation ถูกต้อง และ legacy scope ขยายเฉพาะ key ว่าง
  5. deploy Vercel production ด้วย VERCEL_TOKEN จาก .env.local โดยไม่พิมพ์หรือบันทึก secret
  6. smoke Stock, POS, QR, cancel/void, Inventory API 401/403/200 และ low-stock notification แล้วปิด maintenance

Rollback runbook

  1. หยุด writes และ revert/promote application version ก่อน Stock Pool
  2. เก็บ tables, compatibility columns และ movement ledger ไว้ ห้าม drop table/column ใน release นี้
  3. ปิด entry point/feature flag ของ Stock Pool หาก UI ต้องถูกพัก แล้วใช้ข้อมูล compatibility เดิมระหว่างสืบสวน
  4. หาก migration transaction fail ให้ยืนยันว่า rollback ครบ; หาก apply สำเร็จแต่ app smoke fail ให้ rollback app ก่อน ไม่เขียน SQL ล้างข้อมูลแบบ ad-hoc
  5. กู้ backup เฉพาะเมื่อได้รับอนุมัติแยกและมีหลักฐานว่าจำเป็น

ข้อจำกัดที่ยังเหลือ

  • ผู้ใช้สั่งข้าม Docker จึงไม่มี local PostgreSQL migration/concurrency evidence
  • Browser automation ถูก environment ปฏิเสธด้วย EPERM ที่ AppData; ต้องทำ production smoke หลัง deploy
  • External provider ไม่รับประกัน distributed exactly-once; partial-channel retry อาจทำให้ channel ที่ส่งสำเร็จแล้วถูกส่งซ้ำ
  • ห้ามถือว่า release เสร็จจนกว่า DB invariants, deployment READY และ production smoke ผ่าน

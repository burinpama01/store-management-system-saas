พฤติกรรมที่ผู้ใช้ยืนยัน

ตรวจความพร้อม Beam ก่อนเริ่มรายการใหม่ เมื่อ Beam เชื่อมต่อไม่ได้หรือไม่พร้อม ให้ระบบใช้ PromptPay + Slip2Go อัตโนมัติ ไม่มีปุ่มให้ลูกค้าเลือก fallback ระหว่างจ่าย

รายการที่ค้างอยู่มีลำดับก่อนการตรวจระบบใหม่ การตรวจล่วงหน้าไม่รับประกันเครือข่ายหลังจากนั้น จึงเก็บ reference และ idempotency เดิมไว้เพื่อป้องกันการสร้างรายการจ่ายซ้ำ

สิ่งที่แก้แล้ว

  • ตั้งค่าบัญชี Beam ของแพลตฟอร์มแยกจากบัญชีร้าน พร้อมเข้ารหัส credential และแสดงเฉพาะสถานะ/ค่าปิดบัง
  • ตรวจ Beam ด้วย GET แบบอ่านอย่างเดียวก่อนบันทึกและ POST charge เฉพาะ HTTP สำเร็จถือว่าพร้อม
  • server เป็นผู้เลือก Beam หรือ PromptPay จากผลตรวจและ config ไม่มี method ให้ client เลือก
  • ใช้ Slip2Go adapter เดิม ส่งเงื่อนไขบัญชีผู้รับและยอด รับเฉพาะ code 200000 แล้วตรวจเวลาและเลขอ้างอิง
  • signed webhook และ lookup ยืนยัน THB/ยอด/reference, atomic RPC ป้องกันเครดิตซ้ำ, Playground ไม่เปิดสิทธิ์จริง
  • แก้ findings reviewer เรื่อง pending ถูกซ่อนหลังเปลี่ยน provider และปุ่มเริ่มรายการใหม่หลังสำเร็จ

หลักฐานและข้อจำกัด

รอบ preflight ล่าสุด Vitest 67/67 ผ่าน (6 suites รวม UI 4 เคส) ก่อนปรับ preflight ชุดกว้าง 130/130 ผ่าน PostgreSQL transaction ที่รวม migration และ fixture ถูก ROLLBACK หลังทดสอบ ไม่ได้ apply migration ถาวร

Reviewer รอบล่าสุดไม่พบ finding ใหม่ และยืนยัน 2 finding เดิม resolved ตรวจ source/test cases โดยไม่ได้รัน provider จริง

ยังไม่ทดสอบเงินจริง ไม่ทำ authenticated browser UAT ไม่ build ไม่ bump version ไม่ commit ไม่ deploy

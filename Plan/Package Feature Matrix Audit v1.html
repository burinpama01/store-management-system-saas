2. Matrix เทียบกับ code จริง

Feature สถานะปัจจุบัน หลักฐานใน code Gap / สิ่งที่ยังขาด
maxStores matrix-only มีใน billing/types.ts และ test limit เท่านั้น ยังไม่เจอ enforcement ตอนสร้าง store หรือเปิดใช้ multi-store
maxMembers matrix-only มีใน billing/types.ts และ test limit เท่านั้น ยังไม่เจอ enforcement ตอนเชิญ/สร้างสมาชิกทีม
buffetManagement partial settings/buffet/page.tsx, settings/store/actions.ts, settings/store/page.tsx มี gate หน้า settings และ store toggle แล้ว แต่ยังไม่มี test เฉพาะ buffet package gate
stockManagement partial stock/page.tsx, catalog/page.tsx หน้า stock ถูก gate แล้ว แต่ต้องเช็ก server actions stock/catelog ว่ากันการเขียนครบหรือไม่
advancedPrinting matrix-only module printing และ API print มีอยู่ แต่ไม่เจอ usage ของ key นี้ ต้อง gate Bluetooth/USB/IP/advanced adapter, print test, settings UI และ API route
qrOrdering enforced qr/[storeSlug]/[tableId]/page.tsx, actions.ts, settings/store/actions.ts, catalog/page.tsx coverage ดีสุดในกลุ่ม package gate; เหลือเช็ก edge case runtime/QA
lineNotify enforced settings/notifications/actions.ts, settings/diagnostics/actions.ts, api/notify/route.ts, dispatcher gate server มีแล้ว; ต้องคง provider/env readiness แยกจาก package gate
attendanceGps partial attendance/page.tsx, attendance/actions.ts GPS ถูกปิดเมื่อแพ็กเกจไม่ถึง แต่ attendance basic ยังใช้งานได้; ควรมี test package gate เฉพาะ GPS
advancedReports matrix-only reports module/page มีอยู่ แต่ไม่เจอ usage ของ key นี้ ต้องแยก basic report กับ advanced report แล้ว gate UI/query/export
advancedPermissions matrix-only permission resolver/team settings มีอยู่ แต่ไม่เจอ usage ของ key นี้ ต้องนิยามว่า advanced permissions คือ permission override, custom roles, หรือ owner-only feature แล้ว enforce
multiBranchReporting matrix-only reports/store surfaces มีอยู่ แต่ไม่เจอ usage ของ key นี้ ต้อง gate cross-store aggregation, branch selector, export/report รวมหลายสาขา
apiIntegration matrix-only มี src/app/api หลาย route แต่ไม่เจอ usage ของ key นี้ ต้องแยก public/integration API จาก internal API และ gate token/API access สำหรับ Enterprise

3. Pricing copy / plan settings

  • plan_settings.feature_lines มี seed สำหรับ Starter, Standard, Premium, Enterprise และแก้ผ่าน /system/pricing ได้
  • Premium copy ถูกปรับให้ตรงกับ matrix ปัจจุบัน: QR Ordering, LINE Notify, GPS attendance, และ advanced permissions
  • ข้อความบนหน้า pricing เป็น copy/marketing ไม่ใช่ security boundary; enforcement ต้องอยู่ใน server action/API/repository

4. Priority ที่ควรแก้ก่อน

Priority งาน เหตุผล
P0 enforce maxStores และ maxMembers เป็น hard limit ของแพ็กเกจ ถ้าไม่ enforce จะขาย package limit ไม่ได้จริง
P0 enforce advancedPrinting Standard ขึ้นไปถึงควรใช้ advanced printer; ตอนนี้ adapter/API มีแต่ key ไม่ถูกใช้
P1 แยก basic/advanced reports แล้ว enforce advancedReports Standard มีสิทธินี้ แต่ reports ปัจจุบันยังไม่แยกชั้น feature
P1 นิยามและ enforce advancedPermissions Premium ขึ้นไปมีสิทธิ์นี้ แต่ permission system ปัจจุบันยังไม่ผูกกับ package
P2 ออกแบบ Enterprise gates: multiBranchReporting, apiIntegration เป็นฟีเจอร์ Enterprise-only และยังไม่มี usage จริง

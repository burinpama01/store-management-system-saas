เครื่องพิมพ์พักไว้รอเครื่องจริง · วันที่ 6 ตุลาคม 2569

สถานะเอกสาร: แบบเสนอรอบต่อไป ยังไม่มี implementation ของฟังก์ชันในตารางที่ระบุว่าขาด

แนวทางที่แนะนำ

ต่อ React Native เดิม ใช้ backend และกติกาเดียวกับเว็บ เพิ่ม mobile API เป็นชั้นเชื่อมบริการเดิม ไม่คำนวณสิทธิ์หรือยอดเงินจริงจากมือถือเอง รักษาธีม v3 และปุ่มใหญ่สำหรับ iPhone

ทางเลือกผลแลกเปลี่ยน
Native + API เดิม (แนะนำ)รักษา UX ที่ทำแล้วและต่อ hardware ภายหลังได้ ต้องเพิ่ม API และหน้าจอทีละโมดูล
เปิดเว็บในแอปได้หน้าเว็บเร็ว แต่ต้องออกแบบ session/bridge ใหม่และ UX ไม่เท่าหน้า native
เขียนระบบใหม่ทั้งหมดยืดหยุ่นแต่เสี่ยงกติกา/ข้อมูลต่างจากเว็บ จึงไม่แนะนำ

รอบแรกที่เสนอ: กะเงินสด + บิลพัก + รายละเอียดบิล

กะเงินสด

แสดงเปิดกะก่อนขาย และสถานะกะร้านจริง

ปิดกะ: แสดงยอดคาดหมายจาก server → กรอกเงินนับจริง → แสดงส่วนต่าง → ยืนยัน

บิลพัก

ปุ่มพักบิลข้างตะกร้า เปิดรายการบิลพัก เลือกกลับมาขายต่อ

ตรวจราคา/ตัวเลือก/สินค้าอีกครั้งก่อนรับชำระ บิลที่ผลชำระไม่ชัดเจนต้องตรวจสถานะ ห้ามกลับไปขายซ้ำ

บิลวันนี้ / ประวัติ

ค้นหาหมายเลขบิลและวันที่ เปิดรายละเอียดรายการ ยอดรวม สถานะและวิธีชำระ

รอบแรกอ่านข้อมูล ไม่เพิ่มปุ่มยกเลิก/เปลี่ยนการชำระจนเชื่อมสิทธิ์และกติกาเว็บครบ

ลำดับเพิ่ม POS ให้ครบ

ส่วนหลักฐานโค้ดเว็บสถานะแอป / งานต่อ
ขายสินค้า/ตัวเลือก/ตะกร้าcheckoutAndPayAction / submitOrderActionมีพื้นฐานเงินสดและโอน; รักษา idempotency/pending safeguards
กะเงินสดopenCashSessionAction / closeCashSessionActionยังไม่มีหน้าจอ native; ใช้ RPC/สิทธิ์เดิม ห้ามเปิดซ้ำ
บิลพักและประวัติlistSavedTicketsAction / saveSavedTicketAction / listOrdersHistoryActionnative ยังมีบิลวันนี้แบบรายการ; เพิ่ม API scoped ร้าน/user และรายละเอียด
ลูกค้า/คูปอง/ส่วนลดsearchPosCustomersAction / evaluatePosCouponActionเพิ่มในรอบถัดจากบิล โดยยอดสุดท้ายให้ server ตรวจ
โต๊ะ/ครัว/QR orderslistTableBillsAction / openTableAction / fetchKitchenQueueActionเพิ่ม flow ร้านอาหารและกติกาเปลี่ยนสถานะเดิม
ชำระ QR/Beam/TrueMoneyprepareBeamQrAction / getBeamPaymentStatusAction / prepareTrueMoneyQrActionยังไม่มี native flow; server เป็นผู้ยืนยันชำระ ไม่ยืนยันจากหน้าจอ QR
ยกเลิก/แก้วิธีชำระ/ใบเสร็จvoidOrderAction / changeOrderPaymentMethodAction / getReceiptLoyaltyClaimActionแยกสิทธิ์และ canonical receipt ก่อนเปิดใช้ ไม่พึ่ง summary order เป็นใบเสร็จเต็ม
เครื่องพิมพ์ Bluetoothv0.4.0 native BLEพักงานตามผู้ใช้ รอเครื่องจริง ไม่แก้ต่อรอบนี้

หลัง POS: ทุกโมดูลตามสิทธิ์บัญชี

สินค้า/คลังและสต็อก → ลูกค้าและสมาชิก → เดลิเวอรี/ครัว/บุฟเฟต์ → รายงาน/บัญชี → พนักงาน/เวลาเข้างาน → ตั้งค่าร้าน/สาขา/ทีม/การเชื่อมต่อ/แจ้งเตือน → เสียงและโมดูลอื่นที่ร้านมีสิทธิ์ใช้งาน

รายการนี้เป็นลำดับงาน ไม่ใช่การยืนยันว่าทุกหน้าจอมีแล้ว ต้องทำ checklist ระดับ action ของแต่ละโมดูลก่อนเริ่มรอบนั้น

วิธีตรวจแต่ละรอบ

  • API ใช้บริการเว็บเดิม ยืนยัน bearer/user/store/permission ไม่เพิ่ม migration หาก schema เดิมรองรับ
  • เพิ่มเทสต์กันร้านอื่น/สิทธิ์ไม่พอ/ยอดผิด/คำขอซ้ำและผลไม่ทราบ ไม่เขียนกติกาเงินจริงใหม่
  • UI มือถือ: keyboard ไม่บังสินค้า ปุ่มอย่างน้อย48px มี loading/error/empty และทดสอบแนวตั้ง/แนวนอน
  • code_reviewer → แก้ findings → tests/TypeScript/bundle → commit/push → Codemagic/device UAT เป็นหลักฐานคนละชั้น
  • ไม่ deploy prod หรือทำรายการใหม่บน prod อัตโนมัติในขั้นออกแบบ

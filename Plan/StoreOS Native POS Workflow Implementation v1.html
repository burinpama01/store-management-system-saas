เป้าหมาย: เพิ่มสามส่วนที่ผู้ใช้อนุมัติบน React Native โดยใช้บริการเว็บและสิทธิ์เดิม

Architecture: API adapter ภายใต้ bearer/store context เรียกบริการเว็บเดิม แยก POS workflow component จาก App; รักษา checkout idempotency โดยใช้ claim ID เดิม และเพิ่ม migration บิลพัก native แบบ durable

Stack: Next.js/Supabase/Zod + React Native/Expo/Vitest

1. API — ทำแล้ว ตรวจ local ผ่าน

  1. สร้าง tests/unit/native-pos-workflow.test.ts ทดสอบ permission, cash input, ticket catalog validation, order history bounds
  2. สร้าง src/modules/native-pos/workflow.ts และ contract เพิ่ม DTO/schemas
  3. เชื่อม src/app/api/mobile/pos/[operation]/route.ts หลัง user/store/billing guard
  4. ใช้ cashflow repository + POS/cash actions เดิม เพิ่ม migration 20261006000001_native_pos_ticket_claims.sql ยังไม่ apply prod

2. Native UI — ทำแล้ว browser demo ผ่าน

  1. สร้าง mobile/pos-native/src/PosWorkflow.tsx: cash form, saved bills list, history filters/detail
  2. เพิ่ม draft lifecycle guard ไม่เรียกพักบิลตอน pending checkout; เรียกกลับไม่ทับตะกร้ามีสินค้า
  3. claim แบบ atomic และเก็บผล durable; recovery ใช้ claim ID เดิมกับ checkout ไม่สร้าง ID ใหม่
  4. กรณีข้อมูลนอก subset native (unit/discount/table/customer) ต้องไม่เปิดขายต่อแบบสูญข้อมูล ให้ไปจัดการบนเว็บ
  5. เพิ่ม client-domain tests สถานะคำขอไม่ทราบ/ราคาสินค้าเปลี่ยน/store switch

3. Review / Verify / Release — review ผ่าน กำลังตรวจ release

  1. รัน tests targeted และ TypeScript ทั้ง backend/native
  2. ตรวจ browser390px/keyboard/error/empty/state และ iOS bundle
  3. ส่ง code_reviewer แก้ findings แล้วตรวจซ้ำเฉพาะประเด็น
  4. Bump backend/native version ก่อน build/commit; exact stage ไม่รวม backend dirty จากงานก่อน
  5. บันทึก Obsidian; push branch API/Native แยกกัน และสร้าง PR backend ให้ review ก่อน prod deployment

ข้อจำกัด: รอบนี้พัก Bluetooth; ไม่ deploy production หรือทำเงินจริงใหม่โดยอัตโนมัติ; ทดสอบ production Main Branch ตามขอบเขตที่อนุญาตเดิมเมื่อ release gate พร้อม

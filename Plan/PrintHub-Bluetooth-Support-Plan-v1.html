แผน: ขยาย StoreOS Print Hub ให้รองรับเครื่องพิมพ์ Bluetooth

เวอร์ชัน v1 · 2026-06-30 · branch feat/qr-self-open-and-package-sync · เป้าหมาย: ให้ร้านที่ใช้ POS บน iPad/iOS (ซึ่งต่อ BT ตรงจากเบราว์เซอร์ไม่ได้) สั่งพิมพ์ออกเครื่องพิมพ์ Bluetooth ได้ โดยให้พีซีแคชเชียร์เป็นตัวพิมพ์ออก BT แทน

1. ปัญหา & แนวคิด

ปัญหา: iOS Safari/Chrome ไม่มี Web Bluetooth API → navigator.bluetooth เป็น undefined → เชื่อมเครื่องพิมพ์ BT ตรงจากเบราว์เซอร์ iPad ไม่ได้ถาวร (แก้ที่ฝั่งเบราว์เซอร์ไม่ได้)

แนวคิด: ใช้ Print Hub ที่มีอยู่แล้ว — แต่ปัจจุบัน Hub พิมพ์ผ่าน LAN TCP (เครื่องพิมพ์ IP) เท่านั้น จึงขยายให้รองรับเครื่องพิมพ์ BT ที่ จับคู่ (pair) กับพีซีแคชเชียร์ Windows เป็น Bluetooth SPP COM port (เช่น COM5)

iPad/iOS (เบราว์เซอร์) └─ POST /api/print/enqueue { printerId } └─ คิว print_jobs (target_kind='bt', target_device='COM5') └─ Hub agent (พีซีแคชเชียร์) long-poll + claim └─ เขียน raster ESC/POS ลง \\.\COM5 ──> เครื่องพิมพ์ BT

ข้อดี: iPad ไม่ต้องยุ่งกับ BT เลย แค่ส่งงานเข้าคิว เหมือนเครื่องพิมพ์ IP ทุกประการ

3. สัญญา/รูปแบบข้อมูล (Contract)

print_jobs (ใหม่)

target_kind  text not null default 'ip' check (in ('ip','bt'))
target_device text          -- COM port เมื่อ kind='bt' เช่น 'COM5'
target_host  text           -- (ปลด not null) ใช้เฉพาะ kind='ip'

poll response job

{ id, kind: 'ip'|'bt', host, port, device, printJobBase64 }

Validation (กันความปลอดภัย)

  • validateHubBluetoothPort: trim → uppercase → /^COM([1-9]\d{0,2})$/ (COM1–COM999) มิฉะนั้น error
  • agent ตรวจ COM port ซ้ำก่อนพิมพ์ (defense-in-depth) ก่อนส่งให้คำสั่ง mode — กัน command injection

4. การพิมพ์ออก COM port บน Windows (agent)

  1. จับคู่เครื่องพิมพ์ BT ใน Windows → ระบบสร้าง "Outgoing" Bluetooth SPP COM port (เช่น COM5)
  2. agent: cmd /c mode COM5: BAUD=9600 PARITY=N DATA=8 STOP=1 (virtual SPP มัก ignore แต่ตั้งไว้กันเหนียว)
  3. เขียน raster bytes ลง \\.\COM5 แบบ chunk + หน่วงเวลา (เหมือน sendToSocket / BLE client เพื่อกัน buffer overrun)

⚠ ส่วนนี้ทดสอบกับฮาร์ดแวร์จริงไม่ได้ในเครื่องพัฒนา — แยกฟังก์ชัน sendToComPort ออกจาก runPollCycle ให้ unit-test ผ่าน DI ได้ และ flag ว่า "รอทดสอบ HW จริง" เหมือนแนวทางเดิมของโปรเจกต์

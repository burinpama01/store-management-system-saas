Goal

เปลี่ยนคิวคำขอเพลงเป็น auto-player: หน้า player เล่นต่อเนื่องเอง, ลูกค้าค้นหา YouTube + ขอเพลง, แทรกคิวเมื่อเพลงจบ, โดเนทแซงคิวด้วย PromptPay+สลิป, ลดงานพนักงาน

Architecture

หน้า player แยก (เหมือน customer-display) ใช้ YouTube IFrame Player API + Supabase realtime sync; queue engine จัดลำดับ donation→FIFO; ค้นหาผ่าน YouTube Data API ฝั่ง server; โดเนท reuse PromptPay/slip2go เดิม; ต่อยอด module music-requests เดิม

Locked Decisions (จากผู้ใช้ 2026-06-29)

เรื่องตัดสินใจ
แหล่งเพลงYouTube IFrame Player API เล่นใน iframe + ค้นหาด้วย YouTube Data API v3 (ฝั่ง server, ซ่อน API key)
โดเนทแซงคิวPromptPay + สลิป — reuse PromptPay payload + slip2go verify เดิม; ยอดมากขึ้น = priority สูงขึ้น; ขั้นต่ำ 10 บาท
ความเป็นส่วนตัวของยอดไม่แสดงยอดโดเนทในทุกรายการ (customer/player/dashboard) — แสดงแค่ป้าย "โดเนท"; ยอดใช้ภายในเพื่อจัดลำดับเท่านั้น
Preview ลำดับคิวตอนลูกค้ากรอกยอด ระบบบอกลำดับที่จะได้โดยไม่เปิดเผยยอดของคิวก่อนหน้า เช่น "ยอดที่คุณระบุจะอยู่ในลำดับ 3 — เพิ่มเงินเพื่อเล่นก่อน"
หน้า playerเปิดเป็นหน้า/แท็บแยก (เหมือนจอลูกค้า) + กัน beforeunload ป้องกันเผลอปิดแล้วเพลงดับ
การแทรกคิวเพลงที่ขอไม่ตัดเพลงปัจจุบัน — เล่นต่อเมื่อเพลงปัจจุบันจบ (ENDED event)
เพลงพื้นฐานร้านร้านตั้ง base playlist (YouTube IDs); เล่นวน/สุ่มเมื่อคิวคำขอว่าง — base playlist ไม่เข้า ตาราง music_requests
อัตโนมัติauto-advance ทุกครั้งที่เพลงจบ; มีโหมด auto-approve (ข้ามการกดอนุมัติของพนักงาน) ตั้งได้ที่ร้าน

Priority / Queue Engine

เมื่อเพลงปัจจุบันจบ ระบบเลือกเพลงถัดไปตามลำดับ:

  1. โดเนทที่ verified เรียง donation_amount DESC แล้ว requested_at ASC
  2. คำขอปกติ ที่ approved (หรือ pending ถ้าเปิด auto-approve) เรียง requested_at ASC (FIFO)
  3. ถ้าคิวว่าง → base playlist ของร้าน (วน/สุ่ม)

โดเนทใหม่ที่ยอดสูงกว่าแซงเฉพาะเพลงที่ "ยังไม่เล่น" — ไม่ตัดเพลงที่กำลังเล่น

ความเป็นส่วนตัวของยอด (บังคับ): ยอดโดเนทเป็นข้อมูลภายในใช้จัดลำดับเท่านั้น — ห้ามส่งยอดของผู้อื่นไป client ทุกกรณี (queue/now-playing/preview ส่งแค่ position + flag "โดเนท") Preview ลำดับคำนวณฝั่ง server: position = 1 + จำนวนโดเนท verified ที่ยังไม่เล่นและยอด ≥ ยอดที่กรอก (+ offset คำขอปกติถ้าจัดหลังโดเนท) แล้วคืนเฉพาะตัวเลขลำดับ

Data Model Proposal

Migration warning: ห้าม apply production โดยไม่ขอ approval แยก; local/preview validate ก่อน

-- supabase/migrations/YYYYMMDDHHMMSS_qr_music_player.sql

-- 1. ขยาย music_requests รองรับ YouTube + โดเนท
alter table music_requests
  add column if not exists youtube_video_id text,
  add column if not exists youtube_title text,
  add column if not exists thumbnail_url text,
  add column if not exists duration_seconds integer
    check (duration_seconds is null or (duration_seconds > 0 and duration_seconds <= 1800)),
  add column if not exists donation_amount numeric(12,2) not null default 0
    check (donation_amount >= 0),
  add column if not exists donation_status text not null default 'none'
    check (donation_status in ('none','pending','verified','rejected')),
  add column if not exists donation_slip_url text,
  add column if not exists donation_ref text;

-- 2. ตั้งค่า player + base playlist ต่อร้าน
create table if not exists store_music_player_settings (
  store_id uuid primary key references stores(id) on delete cascade,
  organization_id uuid not null references organizations(id) on delete cascade,
  player_enabled boolean not null default false,
  auto_approve boolean not null default true,
  donation_enabled boolean not null default false,
  min_donation numeric(12,2) not null default 10 check (min_donation >= 0),
  max_duration_seconds integer not null default 600,
  base_playlist jsonb not null default '[]'::jsonb,   -- [{videoId,title,thumbnailUrl,durationSeconds}]
  licensing_acknowledged_at timestamptz,
  updated_at timestamptz not null default now()
);

-- 3. now-playing สำหรับ sync ไป player/customer (1 แถวต่อร้าน)
create table if not exists store_now_playing (
  store_id uuid primary key references stores(id) on delete cascade,
  music_request_id uuid references music_requests(id) on delete set null,
  source text not null default 'base' check (source in ('request','base')),
  youtube_video_id text,
  title text,
  started_at timestamptz not null default now(),
  duration_seconds integer,
  updated_at timestamptz not null default now()
);

alter table store_music_player_settings enable row level security;
alter table store_now_playing enable row level security;
-- RLS: store member read/update settings ผ่าน permission; now_playing เขียนผ่าน RPC/service เท่านั้น
-- realtime: store_now_playing, music_requests (มีอยู่แล้ว)

Acceptance Criteria

  • หน้า player เล่น base playlist ต่อเนื่องเองโดยไม่ต้องแตะ; เพลงจบ → เล่นถัดไปอัตโนมัติ
  • ลูกค้าค้นหา YouTube + ขอเพลง → แทรกคิวเล่นหลังเพลงปัจจุบันจบ (ไม่ตัดเพลง)
  • โดเนท verified แซงคิวตามยอด; ยอดสูงกว่าอยู่ก่อน; ขั้นต่ำ 10 บาท
  • โดเนท verify ฝั่ง server (PromptPay+สลิป) เท่านั้น; กันสลิปซ้ำ/ปลอม
  • ไม่แสดงยอดโดเนทในทุกรายการ (customer/player/dashboard) — แสดงแค่ป้าย "โดเนท"; payload ที่ส่ง client ต้องไม่มียอดของผู้อื่น
  • ตอนกรอกยอดโดเนท แสดงลำดับคิวที่จะได้ ("...จะอยู่ในลำดับ N เพิ่มเงินเพื่อเล่นก่อน") โดยไม่เปิดเผยยอดของคิวก่อนหน้า
  • ปิด/รีเฟรชแท็บ player แล้ว resume จาก now-playing; beforeunload เตือน
  • auto-approve เปิด/ปิดได้; ปิดแล้วต้อง approved ก่อนเข้าคิว
  • วิดีโอ embed ไม่ได้/เล่นไม่ได้ → ข้ามอัตโนมัติ
  • คง gate Enterprise+license เดิม; licensing disclaimer ต้อง ack ก่อนเปิด player
  • tests/typecheck/lint ผ่าน หรือบันทึก blocker ชัด

Stop Conditions

  • ต้อง apply migration prod / deploy โดยไม่ได้ approve
  • ขาด YOUTUBE_API_KEY หรือ quota หมด → หยุดรายงาน
  • โดเนท verify ฝั่ง client ได้ (ต้อง server-only)
  • สลิปซ้ำผ่าน verify ได้ / โดเนทไม่จ่ายแต่แซงคิวได้
  • ยอดโดเนทของผู้อื่นหลุดไป client (queue/now-playing/preview ต้องไม่มียอด)
  • player เล่นต่อเนื่องไม่ได้เพราะ autoplay policy แก้ไม่ตก

Out of Scope (v1)

  • Spotify/Apple Music playback, multi-room sync, offline
  • การเคลียร์ค่าลิขสิทธิ์เพลง (เป็นภาระร้าน) — แค่ disclaimer + ack
  • คืนเงินโดเนท/ระบบบัญชีโดเนทเชิงลึก (บันทึกยอดพอ)
  • AI recommend/auto-DJ เลือกเพลงเอง

Risks to Focus

  • YouTube ToS/quota; วิดีโอ region-block/embed-disabled → ต้อง fallback
  • Browser autoplay policy → ต้องมี gesture เริ่ม + คงแท็บเปิด
  • โดเนท fraud (สลิปปลอม/ซ้ำ) → verify server + ref unique
  • Race: 2 player tab/หลายจอ → now-playing single-row + advance atomic (RPC)
  • Public route leak; คง Enterprise/license enforcement ที่ server

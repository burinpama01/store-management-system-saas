พบจริง

พูดว่า “ลาเต้สองแก้วกับอเมริกาโน่ร้อนหนึ่งแก้ว” แล้วโมเดลแถม pos.clear_search มาด้วย

สิ่งที่แก้:

  • timeout เปลี่ยนเป็นค่าเริ่มต้น 6000ms และ override ได้ด้วย AI_VOICE_INTENT_TIMEOUT_MS (ตั้ง 2000 เพื่อกลับไปตามแผนเดิมได้ทันที) — ต้องวัด p95 จริงตอน pilot แล้วตัดสินใจอีกครั้ง
  • รับ pos.clear_search ได้เฉพาะเมื่อเป็นคำสั่งเดียวใน batch — ไม่มีใครสั่งเพิ่มสินค้าพร้อมล้างคำค้นในประโยคเดียว

5. ยังไม่ผ่าน / ยังทำไม่ได้

  • ยังไม่ได้ทดสอบด้วยไมค์จริง — Chromium headless ไม่มี Web Speech API จึงกดปุ่มแล้วพูดจริงไม่ได้ ต้องมีคนทดสอบบนเครื่องที่มีไมค์
  • corpus เสียงจริง ≥400 ประโยค ≥10 ผู้พูด เงียบ/มีเสียงรบกวน — ยังไม่มี (ที่ทำไว้เป็น corpus สังเคราะห์ 33 ประโยค คุมได้แค่ตรรกะการตัดสินใจ)
  • accuracy ≥95% / clarify ≥99% / p95 ≤ เป้าหมาย — วัดไม่ได้จนกว่าจะมี corpus จริง
  • pilot 1 ร้าน 7 วัน แล้ว 3 เครื่อง 14 วัน — ยังไม่เริ่ม
  • P8 Windows Standby — ยังไม่มีของให้ต่อ

6. การเปิดใช้งานและการถอย

ชั้นค่าผลเมื่อปิด
เสียงทั้งระบบstores.voice_command_enabledไม่มีปุ่มเสียงเลย (เหมือนก่อนมีฟีเจอร์)
AI fallbackprop aiFallbackEnabled ของ VoicePosControllerเหลือ deterministic voice เดิมทั้งหมด ไม่มี request ออกนอกเครื่อง
แพ็กเกจaiAssistant (enterprise)API ตอบ 403 พร้อมทางออกด้วยมือ
ระบบ AIOPENAI_API_KEYAPI ตอบ 503 พร้อมทางออกด้วยมือ
โควตาAI_MONTHLY_TOKEN_BUDGET · feature aiVoiceIntentAPI ตอบ 429 พร้อมทางออกด้วยมือ

หมายเหตุ: aiFallbackEnabled ยังไม่ถูกต่อเข้ากับ flag ของร้านในหน้า POS จริง (ค่าเริ่มต้นคือ false) — ต้องตัดสินใจว่าจะผูกกับ flag ตัวใหม่หรือ reuse ตัวเดิม ก่อนเปิด pilot

7. ขั้นถัดไป

  1. ทดสอบด้วยไมค์จริงบนเครื่องที่มี Web Speech (พูดหลายเมนูในประโยคเดียว, เมนูที่ต้องเลือกตัวเลือก, คำสั่งต้องห้าม)
  2. ตัดสินใจว่าจะผูก aiFallbackEnabled กับ flag ตัวไหน แล้วเปิดเฉพาะร้านทดสอบ
  3. วัด p95 latency จริง แล้วสรุปค่า timeout (คงที่ 6s หรือกลับไป 2s ตามแผน)
  4. เก็บ corpus จากการใช้งานจริงแบบมี consent เพื่อวัด accuracy
  5. อนุมัติ deploy → merge → push (ยังไม่ทำในรอบนี้ตามคำสั่งผู้ใช้)

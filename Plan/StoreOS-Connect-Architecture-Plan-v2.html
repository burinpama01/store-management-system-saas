0. อะไรเปลี่ยนจาก v1

Decision ใหม่ (ผู้ใช้ยืนยัน): กดสถานะออเดอร์ได้ ทั้งสองฝั่ง — JDC merchant app และ StoreOS POS sync หากันแบบ real-time
หัวข้อv1v2 (ฉบับนี้)
Flow สถานะStoreOS → JDC อย่างเดียวสองทาง StoreOS ⇄ JDC
กัน loop/echo—ใหม่ origin tagging ทั้ง 2 ฝั่ง (§8)
เลือกสินค้า/ราคา JDCกล่าวลอย ๆใหม่ field available_for_delivery + delivery_price (§5, §6)
โมเดลเงินเปิดคำถาม settlementปิดแล้ว: เงินไม่ผ่าน StoreOS, แค่ mark "ชำระโดย JDC"

1. วิสัยทัศน์ & โมเดล

เชื่อม StoreOS (POS หลังร้าน) เข้ากับ JDC (แอปเดลิเวอรี) ผ่านตัวกลาง StoreOS Connect โดยจำลองโมเดล LINE MAN × Wongnai POS

หลักการ 4 ข้อ:
  • POS เป็นแหล่งความจริงของเมนู — จัดการเมนู/ราคา/สต็อกที่เดียวแล้วดันขึ้น JDC
  • ออเดอร์จาก JDC ไหลเข้า POS อัตโนมัติ
  • สถานะ sync สองทาง real-time — กดที่ไหนก็ได้ อีกฝั่งเห็นทันที
  • เปิด-ปิดร้าน & ของหมด sync
ข้อค้นพบที่กำหนดสถาปัตยกรรม: StoreOS (lcsxee…) กับ JDC (tfwhf…) อยู่ คนละ Supabase project → Connect = API/Event bridge ระหว่าง 2 ฐานข้อมูล (ตรงโมเดล LINE MAN × Wongnai)

5. ตารางข้อมูลใหม่ (ฝั่ง StoreOS)

-- 1) ผูกร้าน ↔ ช่องทางขายภายนอก
create table connect_channel_links (
  id uuid primary key default uuid_generate_v4(),
  organization_id uuid not null references organizations(id) on delete cascade,
  store_id uuid not null references stores(id) on delete cascade,
  channel text not null default 'jdc',
  external_merchant_id text not null,        -- profiles.id ฝั่ง JDC
  status text not null default 'active',
  webhook_secret text not null,              -- HMAC (เก็บ encrypted/ref)
  jdc_functions_base_url text not null,      -- ปลายทาง Edge Functions ฝั่ง JDC
  auto_accept boolean not null default false,
  config jsonb not null default '{}',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (store_id, channel)
);

-- 2) แผนที่สินค้า ↔ เมนูปลายทาง
create table connect_menu_map (
  id uuid primary key default uuid_generate_v4(),
  link_id uuid not null references connect_channel_links(id) on delete cascade,
  product_id uuid not null references products(id) on delete cascade,
  external_item_id text, sync_hash text, last_synced_at timestamptz, last_error text,
  unique (link_id, product_id)
);

-- 3) ออเดอร์ที่รับเข้า (idempotency + fulfillment สถานะครัว)
create table connect_orders (
  id uuid primary key default uuid_generate_v4(),
  organization_id uuid not null references organizations(id) on delete cascade,
  link_id uuid not null references connect_channel_links(id) on delete cascade,
  external_order_id text not null,           -- bookings.id ฝั่ง JDC
  internal_order_id uuid references orders(id) on delete set null,
  channel text not null default 'jdc',
  fulfillment_status text not null default 'received', -- received|accepted|preparing|ready|completed|cancelled
  last_status_origin text,                   -- 'jdc'|'storeos' ★ กัน loop (v2)
  raw_payload jsonb not null,
  received_at timestamptz not null default now(),
  unique (link_id, external_order_id)
);

-- 4) คิว event สองทาง + retry + audit
create table connect_events (
  id uuid primary key default uuid_generate_v4(),
  link_id uuid not null references connect_channel_links(id) on delete cascade,
  direction text not null, topic text not null, payload jsonb not null,
  status text not null default 'pending', attempts int not null default 0,
  next_retry_at timestamptz, last_error text, created_at timestamptz not null default now()
);

-- 5) field ใหม่ใน products (v2) — เลือกสินค้า/ราคา JDC
alter table products add column if not exists available_for_delivery boolean not null default false;
alter table products add column if not exists delivery_price numeric(12,2);  -- null = ใช้ base_price
สถานะครัวเดลิเวอรี: orders.status เดิม (draft/open/paid/…) ไม่มี accepted/preparing/ready → ใช้ connect_orders.fulfillment_status + ผูก kitchen ticket เดิม. ออเดอร์ JDC ตั้ง orders.status='paid' ทันที (ชำระโดย JDC)

6. การ map ข้อมูล

6.1 สินค้า → เมนู products → menu_items

StoreOSJDCหมายเหตุ
available_for_delivery=true→เงื่อนไขว่าจะดันหรือไม่v2 sync เฉพาะที่ติ๊ก
delivery_price ?? base_price→pricev2 ราคา JDC แยกจากหน้าร้าน
id→external_ref (+ menu_map)คีย์เชื่อม
name/description/image_url→เหมือนกันตรง
is_active AND สต็อก→is_availableรวมของหมด
ชื่อ category (จาก FK)→category (text)ส่งชื่อหมวด

6.2 ออเดอร์ bookings + booking_items → orders + order_items

JDCStoreOSหมายเหตุ
bookings.id→connect_orders.external_order_ididempotency
booking_items.menu_item_id→order_items.product_idmap ย้อนผ่าน menu_map
quantity/price/name→quantity/unit_price/product_nameตรง
ยอด + paid:true→total, status=paidชำระโดย JDC

F1. Sync เมนู/ราคา/สต็อก StoreOS → JDC

1
ร้านแก้สินค้า/ติ๊ก available_for_delivery/ตั้ง delivery_price หรือกด "เผยแพร่ขึ้น JDC" → event menu.upsert
2
Connect map ตาม §6.1 (ส่งเฉพาะที่ติ๊ก, ราคา = delivery_price??base_price) → เทียบ sync_hash
3
เรียก JDC connect_upsert_menu (HMAC) → upsert menu_items
4
บันทึก external_item_id+last_synced_at; ของหมด → is_available=false
cron reconcile รายชั่วโมง + ปุ่ม "Sync ทั้งหมด" สำหรับ initial load

F2. รับออเดอร์เข้า POS JDC → StoreOS

1
ลูกค้าสั่งใน JDC → สร้าง booking (food) + ชำระออนไลน์
2
trigger JDC ยิง webhook order.created → POST /api/connect/v1/webhooks/jdc/order (HMAC+ts)
3
Connect verify → idempotency ด้วย booking.id → map รายการ → สร้าง orders(status=paid)+order_items + connect_orders (fulfillment=received)
4
โผล่บน POS/KDS + พิมพ์ตั๋วครัว; ถ้า auto_accept → ไป F3
webhook ตอบ 2xx เร็ว (รับเข้า inbox ก่อน) + JDC retry + idempotency กันซ้ำ

F3. สถานะออเดอร์ สองทาง StoreOS ⇄ JDC เปลี่ยนใน v2

3A. ร้านกดในแอป JDC → StoreOS

1
ร้านกดรับ/อาหารพร้อม (status_origin='jdc')
2
trigger ยิง order.status → webhook StoreOS
3
Connect อัปเดต fulfillment_status (ไม่ push กลับ) → POS เห็นสถานะ live

3B. พนักงานกดใน StoreOS POS → JDC

1
พนักงานกดรับ/พร้อม บน POS/KDS
2
set fulfillment_status (origin=storeos) → event order.status
3
เรียก JDC connect_update_order_status (set status_origin='storeos' ฝั่ง JDC → ไม่ยิงกลับ)
4
JDC จ่ายงานคนขับ + แจ้งลูกค้า
StoreOS set ได้เฉพาะ: preparing / ready_for_pickup / cancelled — สถานะของคนขับ (matched/driver_accepted/in_transit) เป็นของ JDC ห้ามแตะ (ดู §8)

F4. เปิด-ปิดร้าน & ของหมด

1
เปิด/ปิดรับเดลิเวอรีใน StoreOS → event shop.status → JDC connect_set_shop_status เซ็ต profiles.shop_status
2
สินค้าหมดใน StoreOS → menu.upsert (is_available=false)

7. API Contract

ขาเข้า StoreOS (JDC เรียก)

POST /api/connect/v1/webhooks/jdc/order
Headers: X-Connect-Signature: sha256=...   X-Connect-Timestamp: ...
Body: { topic:'order.created'|'order.status', booking_id, merchant_id, status,
        items:[{menu_item_id,qty,price,name}], customer, dropoff, total, paid:true, ts }
→ 202 { received:true }

ขาออก StoreOS (เรียก JDC Edge Functions)

POST {jdc}/functions/v1/connect_upsert_menu          { merchant_id, items[], full_sync }
POST {jdc}/functions/v1/connect_update_order_status  { booking_id, status }   ← v2 จำเป็น
POST {jdc}/functions/v1/connect_set_shop_status      { merchant_id, is_open }

8. กัน Loop ในการ sync สองทาง (หัวใจของ v2)

ปัญหา: A อัปเดต B → B แจ้งกลับ A → A อัปเดต → วนไม่จบ · แก้ด้วย origin tagging ทั้ง 2 ฝั่ง

เหตุการณ์ใครเขียนoriginยิงข้ามฝั่ง?
ร้านกดในแอป JDCJDC appjdc✓ JDC→StoreOS
พนักงานกดใน POSStoreOSstoreos✓ StoreOS→JDC
JDC รับ update จาก StoreOSEdge Fnเขียน storeos✗ trigger เห็น origin=storeos → ข้าม
StoreOS รับ webhook จาก JDCConnectset last_status_origin=jdc✗ ไม่ push กลับ
กฎทอง: emit เฉพาะการเปลี่ยนที่เกิดจากผู้ใช้ฝั่งตัวเอง + ถ้า status ที่รับ = ปัจจุบันอยู่แล้ว → no-op (idempotent)

9. Security & Reliability

ความปลอดภัย

  • HMAC สองทาง + timestamp กัน replay (≤5 นาที)
  • ไม่เก็บ service key/secret ของ JDC แบบ plaintext — ใช้ Vercel env / secret store
  • ต่อยอด api_keys + scope connect + Enterprise gate
  • RLS org-scoped ทุกตาราง connect_*

ความทนทาน

  • Outbox/Inbox + retry backoff → dead-letter
  • Idempotency: order=booking_id, menu=sync_hash, status=no-op เมื่อซ้ำ
  • กัน loop: origin tagging (§8)
  • Reconcile cron + หน้า admin retry event fail
Blocker (AGENTS.md): secret/JDC keys ต้องตั้งใน Vercel env ก่อน deploy — ขอจากผู้ใช้

10. Roadmap & Phase

Phase 0 — ฐานราก
  • migration connect_* 4 ตาราง + RLS + products.available_for_delivery/delivery_price
  • โมดูล src/modules/connect/ (repo, mapping, JDC client, hmac)
  • หน้า admin ผูกร้าน + gen secret · API contract spec ส่งให้ JDC
Phase 1a — Menu/Price/Stock sync (F1 + F4 ของหมด) — เลือกสินค้า + delivery_price
Phase 1b — รับออเดอร์เข้า POS (F2) — webhook in + map + KDS/ตั๋วครัว + mark paid
Phase 1c — สถานะสองทาง + เปิด-ปิดร้าน (F3 3A+3B, F4) — origin tagging + ปุ่มสถานะบน POS
Phase 2 — reconcile cron, dashboard retry, รายงานยอดเดลิเวอรี, auto-provision linking
Phase 3 — multi-channel abstraction (รองรับ LINE MAN/Grab จริง)

ลำโพงแจ้งเตือน/เพลงแยก + Launcher อัปเดตตัวเอง v2

StoreOS · 2026-09-19 · Launcher 0.4.1 → 0.5.0 · สถานะ: อนุมัติแล้ว 2026-09-19 (ใช้ค่าที่แนะนำ L1–L4) · v2 เพิ่ม A3 เลือกลำโพงของเพลง · แทรกก่อนเฟส 3 ของแผนพิมพ์ตั๋วครัว

โจทย์: พีซีแคชเชียร์ต่อลำโพง 2 ตัว — ตัวหนึ่งเล่นเพลงร้าน (เครื่องเล่นเพลงเปิดใน Launcher) อีกตัวรับเสียงแจ้งเตือนจาก POS · และตั้งแต่เวอร์ชันนี้ Launcher ต้องแจ้งและอัปเดตตัวเองได้เมื่อมีรุ่นใหม่

ทำไมแยกด้วย Windows ไม่ได้: เพลง (/player) และเสียง POS อยู่ในโปรแกรมเดียวกัน (WebView2 ของ Launcher) — Windows เลือกลำโพงได้ทีละโปรแกรม

ส่วน A — Launcher เล่นเสียงแจ้งเตือนเองผ่านลำโพงที่เลือก

A1. Launcher (C#)

  • เพิ่มแพ็กเกจ NAudio (MIT) — MMDeviceEnumerator ลิสต์ลำโพงของ Windows (ชื่อจริง ไม่ต้องขอสิทธิ์ไมค์แบบเว็บ) + WasapiOut เล่นออกอุปกรณ์ที่ระบุ
  • Services/AlertPlayer.cs: ฝังไฟล์ AlertNewOrder.mp3 + สังเคราะห์ beep 2 แบบ (qr/connect) ในหน่วยความจำ · เล่นซ้อนได้ไม่ค้าง · ลำโพงที่เลือกถูกถอด → ใช้ลำโพงหลักของ Windows แทน + log + แจ้งหน้าเว็บ
  • launcher.json เพิ่ม AlertOutputDeviceId (null = ตามลำโพงหลักของ Windows) + AlertVolume (0–100)
  • ข้อความผ่านสะพาน chrome.webview (รับเฉพาะจาก origin ของ StoreOS แบบเดียวกับ provision):
เว็บ → Launcher   {type:"alert.play", sound:"order"|"qr"|"connect"}
เว็บ → Launcher   {type:"alert.devices.get"}
เว็บ → Launcher   {type:"alert.config.set", deviceId|null, volume}
เว็บ → Launcher   {type:"alert.test"}
Launcher → เว็บ   {type:"alert.devices", devices:[{id,name,isDefault}], selectedId, volume}
Launcher → เว็บ   {type:"launcher.hello", version, capabilities:["alert-player","self-update",...]}

A2. หน้าเว็บ

  • windows-host.ts: รู้ว่ารันใน Launcher ที่รองรับ alert-player หรือไม่ (จาก launcher.hello)
  • alert-sound.ts: ถ้ามี alert-player → ส่ง alert.play แทนการเล่นด้วย Web Audio (ทั้งเสียงออเดอร์และ beep) · ไม่มี (เบราว์เซอร์ปกติ/ Launcher รุ่นเก่า) → เล่นเองเหมือนเดิม
  • การ์ด "ลำโพงเสียงแจ้งเตือน (เครื่องนี้)" แสดงเฉพาะตอนเปิดใน Launcher: เลือกลำโพง · ปรับความดัง · ปุ่ม "ทดสอบเสียง" — วางในหน้า ตั้งค่า → การแจ้งเตือน (และลิงก์จากแถบสถานะ POS)
  • ได้ของแถม: เสียงดังตั้งแต่เปิดเครื่องโดยไม่ต้องมีคนแตะจอ (Launcher เล่นเองไม่ติดกติกา autoplay)

A3. เลือกลำโพงของเพลง (/player) — เพิ่มใน v2 ตามคำขอผู้ใช้

  • ค่าเริ่มต้น = ลำโพงหลักของ Windows (ไม่แตะอะไรเลย) · เลือกได้ในการ์ดเดียวกัน ("ลำโพงเพลง")
  • เพลงเล่นผ่าน YouTube iframe — หน้าเว็บเลือกลำโพงให้ iframe ไม่ได้ จึงให้ Launcher ตั้งลำโพงระดับ Windows ให้ process เสียงของ WebView2 (audio service ของ Launcher) ด้วย API นโยบายเสียงของ Windows ต่อ process (วิธีเดียวกับ EarTrumpet)
  • ทำได้เพราะเสียงแจ้งเตือนย้ายไปเล่นจากตัว Launcher (NAudio) แล้ว — เสียงที่เหลือใน WebView2 คือเพลง (และเสียงพูดประกาศ)
  • ตรวจ process เสียงใหม่เป็นระยะ (WebView2 สร้างใหม่ได้) แล้วตั้งซ้ำ · เลือก "ลำโพงหลักของ Windows" = ล้างค่ากลับเป็นปกติ
  • ความเสี่ยง: เป็น API ที่ Microsoft ไม่ได้ประกาศเป็นทางการ (ใช้กันแพร่หลาย) — ถ้าใช้ไม่ได้บนเครื่องไหน Launcher จะ log และการ์ดขึ้นคำแนะนำให้ตั้งใน Volume mixer ของ Windows แทน · เสียงพูดประกาศออเดอร์จะออกลำโพงเดียวกับเพลง
ข้อจำกัด: เสียงพูดประกาศออเดอร์ (speechSynthesis ของเบราว์เซอร์) ยังออกลำโพงหลัก — ถ้าต้องการให้ย้ายตามด้วย ทำต่อได้โดยให้ Launcher พูดเอง (Windows TTS → ลำโพงที่เลือก) เป็นงานรอบถัดไป

ส่วน B — Launcher อัปเดตตัวเอง (ตั้งแต่ 0.5.0)

B1. ฝั่งเซิร์ฟเวอร์

  • GET /api/launcher/latest?channel=prod (public) คืน {version, url, sha256, size, notes, publishedAt} จาก src/modules/launcher/version.ts (เพิ่ม LAUNCHER_SHA256, LAUNCHER_SIZE, LAUNCHER_NOTES — เทสต์บังคับเลขตรง csproj และรูปแบบ sha256)
  • url ชี้ GitHub Releases launcher-v<ver>/storeos-launcher-<ver>.zip เหมือนลิงก์ดาวน์โหลดเดิม

B2. ฝั่ง Launcher

  1. ตรวจ: ตอนเปิดโปรแกรม + ทุก 6 ชม. + ตอนเครื่องตื่นจาก sleep → เทียบ SemVer
  2. แจ้ง: มีรุ่นใหม่ → แถบสถานะของ Launcher ขึ้น "มีอัปเดต 0.5.1 — [อัปเดตตอนนี้] [ภายหลัง]" + ส่ง launcher.update-available ให้หน้าเว็บโชว์แบนเนอร์เล็ก
  3. ดาวน์โหลดเบื้องหลัง ไป %LOCALAPPDATA%\StoreOS\Launcher-updates\ · รับเฉพาะ URL ของ repo เรา (allowlist) · ตรวจ SHA-256 จากเซิร์ฟเวอร์ (ไม่ตรง = ทิ้ง + log) · แตกไฟล์ไปโฟลเดอร์ staging
  4. ติดตั้ง: กด "อัปเดตตอนนี้" (ยืนยันก่อน — ไม่ปิดกลางการขาย) หรือ ติดตั้งเองตอนเปิดโปรแกรมครั้งถัดไป ก่อนโหลดหน้า POS → ตัวช่วยอัปเดต (StoreOS.Updater.exe เล็ก ๆ ในชุด) รอ Launcher ปิด → ย้ายโฟลเดอร์เดิมเป็น previous\ → วางรุ่นใหม่ → เปิด Launcher
  5. ย้อนกลับอัตโนมัติ: รุ่นใหม่ต้องเขียน "เปิดสำเร็จ" ภายใน 90 วิ ไม่งั้นตัวช่วยคืน previous\ แล้วเปิดรุ่นเดิม + log update_rolled_back
  6. ทุกขั้น log ผ่าน LauncherLogShipper ขึ้นหน้า /system/logs (ตรวจ/ดาวน์โหลด/ไม่ตรง sha/ติดตั้ง/ย้อนกลับ)

ไม่แตะของนอกโฟลเดอร์โปรแกรม: launcher.json (%LOCALAPPDATA%\StoreOSLauncher), โปรไฟล์ WebView2, config Print Hub, scheduled task — อยู่ที่เดิมทั้งหมด

รุ่นแรกต้องลงเองหนึ่งครั้ง: 0.4.1 ยังไม่มีตัวอัปเดต ร้านต้องดาวน์โหลด 0.5.0 มาติดตั้งเองครั้งเดียว (หน้า POS จะเห็นว่ารันใน Launcher รุ่นเก่าแล้วขึ้นแบนเนอร์ชวนดาวน์โหลด) · หลังจากนั้นอัปเดตเองทั้งหมด

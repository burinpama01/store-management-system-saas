แผนส่ง StoreOS POS iOS ให้ผ่าน App Review ก่อน แล้วค่อยเพิ่มฟีเจอร์

สร้าง 2026-11-28 · branch feat/pos-native-ipad · ฐานโค้ด 0.9.0+21 (9d73556) · เสนอ — รออนุมัติ

เป้าหมาย: ส่งรุ่น 1.0.0 ที่มีฟีเจอร์ น้อยแต่ครบในตัว ให้ผ่าน App Review รอบแรก หลังได้ขึ้น App Store แล้วค่อยเปิดฟีเจอร์ทีละชุดในรุ่น 1.1, 1.2, … ซึ่งแต่ละรุ่นต้องส่งรีวิวตามปกติ
ผู้ใช้เลือกแล้ว: ใช้ขอบเขตแบบแนะนำและเพิ่มพิมพ์ WiFi · ตัดโหมดสาธิตออก แล้วส่งบัญชีรีวิวให้ Apple แทน

1. ขอบเขตรุ่น 1.0.0

ฟีเจอร์1.0.0เหตุผล
Login อีเมล/รหัสผ่าน + เลือกร้าน/สาขาเปิดจำเป็น
ขายสินค้า ตะกร้า ตัวเลือกสินค้า รูปสินค้าเปิดฟังก์ชันหลัก
รับเงินสด / Beam QR (แสดงเฉพาะร้านที่ beam-config เปิด)เปิดเป็นการจ่ายค่าสินค้าและบริการในร้านจริง จึงไม่ต้องใช้ IAP (ข้อ 3.1.3(e))
ใบเสร็จบนจอ + QR รับแต้มเปิดผู้รีวิวทดสอบได้โดยไม่ต้องมีเครื่องพิมพ์
กะเงินสด / บิลพัก / ประวัติบิลวันนี้เปิดทำให้แอปไม่บางเกินไป (ข้อ 4.2)
ลูกค้า / ส่วนลดท้ายบิล / คูปอง / แต้มเปิดต้องประกาศใน App Privacy ว่าเก็บเบอร์โทรลูกค้า
พิมพ์ใบเสร็จผ่าน WiFi (LAN)เปิดผู้ใช้เลือก · ต้องทดสอบบนเครื่องจริงก่อนส่ง ถ้าไม่มีเครื่องพิมพ์ต้องแจ้งเตือนเฉย ๆ ห้าม crash
เครื่องพิมพ์ Bluetoothปิดยังไม่เคยทดสอบกับเครื่องจริง หน้าจอยังโชว์ UUID แบบงานนักพัฒนา และถ้าถอด plugin ออก แอปจะไม่ขอสิทธิ์ Bluetooth
AI ช่วยเพิ่มสินค้าปิดข้อความ error พูดถึง "แพ็กเกจที่เปิด AI" ซึ่งอาจถูกมองว่าชวนซื้อนอกแอป (ข้อ 3.1.1) และต้องประกาศว่าส่งข้อความไปประมวลผล AI
เดลิเวอรี (JDC)ปิดบัญชีรีวิวจะเห็นแค่หน้าว่าง ดูเหมือนฟีเจอร์ยังไม่เสร็จ (ข้อ 2.1)
โหมดสาธิตตัดออกผู้ใช้เลือก · ใช้บัญชีรีวิวแทน
ช่อง "ตั้งค่าการเชื่อมต่อร้าน" (แก้ URL เซิร์ฟเวอร์)ซ่อนเป็นเครื่องมือนักพัฒนา ล็อกไว้ที่ prod
กฎสำคัญ: ฟีเจอร์ที่ปิดต้องปิดตอน build ด้วยค่าคงที่ใน src/features.ts ห้ามเปิดจากเซิร์ฟเวอร์หรือ OTA เพราะ Apple ถือว่าเป็น "ฟีเจอร์ซ่อน" (ข้อ 2.3.1 / 2.5.2) ซึ่งอาจโดนปฏิเสธหรือถูกถอดบัญชีนักพัฒนา การเปิดฟีเจอร์เพิ่มในอนาคตต้องออก build ใหม่และส่งรีวิวทุกครั้ง

2. เทียบแนวทาง App Review กับสิ่งที่ต้องทำ

ข้อความเสี่ยงที่จะโดนปฏิเสธสิ่งที่ต้องทำ
2.1 ความครบถ้วนแอป crash, หน้าว่าง, ข้อความ "ยังไม่พร้อม", ข้อความแบบนักพัฒนาลบ "React Native · iPhone / iPad" ในหน้าตั้งค่า ซ่อน BLE diagnostics ส่งบัญชีรีวิวที่มีสินค้าและบิลจริง และทดสอบบน iPhone + iPad จริง
2.1 ข้อมูลสำหรับรีวิวlogin ไม่ได้ = โดนปฏิเสธทันทีสร้างร้าน "StoreOS Review" ใน prod พร้อมบัญชี cashier ใส่ในช่อง App Review Information และเขียนโน้ตภาษาอังกฤษอธิบายว่าเป็นแอป B2B สำหรับร้านที่สมัครบนเว็บ
2.3 metadata ตรงกับแอปscreenshot หรือคำอธิบายพูดถึงฟีเจอร์ที่ปิดอยู่ถ่าย screenshot จาก build 1.0.0 เท่านั้น ทั้ง iPhone 6.9" และ iPad 13" (เพราะ supportsTablet: true)
3.1.1 การซื้อในแอปลิงก์หรือข้อความชวนซื้อแพ็กเกจ StoreOSไม่มีปุ่มสมัคร/ราคา/อัปเกรดในแอป ปรับข้อความ error ที่พูดถึงแพ็กเกจให้เป็นกลาง และไม่ลิงก์ไปหน้าราคา (เข้าข่าย 3.1.3(b) แอปใช้บัญชีที่สร้างนอกแอป)
4.2 ฟังก์ชันขั้นต่ำแอปบางเกินไป หรือเป็นแค่เว็บห่อเป็น native จริง มีขาย/รับเงิน/กะเงินสด/ประวัติ/ลูกค้า ถือว่าผ่าน
5.1.1 ความเป็นส่วนตัวไม่มีลิงก์นโยบาย หรือขอสิทธิ์โดยไม่จำเป็นในหน้าตั้งค่าเพิ่มลิงก์นโยบายความเป็นส่วนตัวและ "ขอลบบัญชี" (/account-deletion) แอปไม่สร้างบัญชีเองจึงไม่บังคับ แต่ใส่ไว้เพื่อตัดความเสี่ยง ถอด plugin BLE ออกเพื่อไม่ขอสิทธิ์ Bluetooth และขอ Local Network เฉพาะตอนผู้ใช้กดพิมพ์/ค้นหาเครื่องพิมพ์
5.1.2 App Privacyประกาศข้อมูลที่เก็บไม่ตรงกับความจริงประกาศว่าเก็บ อีเมล (บัญชี), เบอร์โทร/ชื่อลูกค้า (ใช้งานแอป), ประวัติการซื้อ ไม่ใช้ติดตามข้าม app และไม่มี tracking
Export complianceต้องตอบคำถามเรื่องการเข้ารหัสทุกครั้งที่ส่งใส่ ITSAppUsesNonExemptEncryption = false ใน infoPlist (ใช้แค่ HTTPS)
4.8 Sign in with Apple—ไม่ต้องทำ เพราะใช้บัญชีของ StoreOS เอง ไม่มี login ผ่าน Google/Facebook

3. งานแก้โค้ด (native เท่านั้น ไม่แตะ backend)

  1. เพิ่ม src/features.ts: ค่าคงที่ FEATURES = { ai:false, delivery:false, bluetooth:false, lanPrinter:true, demo:false, serverOverride:false } พร้อม unit test ยืนยันค่าของรุ่น release
  2. App.tsx: กรองแท็บ/ปุ่มตาม FEATURES (เดลิเวอรี, AI ในตะกร้าและหน้าเพิ่มเติม), ลบปุ่ม "ลองหน้าขายแบบสาธิต", ซ่อนช่องแก้ URL และล็อก base เป็น prod, ปรับหน้าตั้งค่าให้มีชื่อร้าน + รุ่นแอป + ลิงก์นโยบาย/ลบบัญชี/ติดต่อ + ออกจากระบบ
  3. เครื่องพิมพ์: หน้าเครื่องพิมพ์โชว์แค่ LAN ส่วน BluetoothSettings ไม่ถูก import เมื่อ bluetooth:false ถอด react-native-ble-plx ออกจาก plugins ใน app.json ส่วน package ยังเก็บไว้เพื่อเปิดกลับในรุ่น 1.2
  4. ข้อความ: ไล่หาคำว่า "แพ็กเกจ / สาธิต / ยังไม่พร้อม / ระบบหลังบ้านรุ่นนี้" ในทางที่ผู้ใช้จะเห็น แล้วเปลี่ยนเป็นข้อความกลาง ๆ
  5. app.json: version 1.0.0, buildNumber ต่อจากเลขล่าสุดใน App Store Connect, ITSAppUsesNonExemptEncryption:false, คง NSLocalNetworkUsageDescription และตรวจ PrivacyInfo ที่ Expo สร้างให้
  6. โค้ดโหมดสาธิต (demo.ts, demo-workflow.ts, ทางแยก isDemo): รอบนี้แค่ทำให้เข้าไม่ถึงตามข้อ 1 ส่วนการลบโค้ดจริงทำเป็นงานแยกหลัง 1.0.0 เพื่อลดความเสี่ยงพังก่อนส่ง

5. ลำดับงานและการตรวจ

  1. แก้โค้ดตามข้อ 3 → เทสต์ native + tsc + iOS JS export
  2. ส่ง code_reviewer รีวิวเฉพาะ diff นี้
  3. สร้างร้านและบัญชีรีวิวใน prod (ต้องขออนุมัติก่อน เพราะเป็นการเขียนข้อมูลลง prod)
  4. Codemagic build → TestFlight → ทดสอบบน iPhone + iPad จริง: login, ขาย, เงินสด, Beam, กะ, พักบิล, ลูกค้า/คูปอง, พิมพ์ WiFi และกรณีไม่มีเครื่องพิมพ์
  5. ถ่าย screenshot → กรอก metadata → ผู้ใช้กด Submit for Review
  6. ถ้าโดนปฏิเสธ: อ่านข้อที่ Apple อ้าง แก้เฉพาะจุดนั้น แล้วส่งใหม่

6. แผนหลังผ่านรีวิว

1.1 AI ช่วยเพิ่มสินค้า + ไมค์ (ต้องเพิ่ม usage descriptions และประกาศการส่งข้อมูลไป AI)
1.2 เครื่องพิมพ์ Bluetooth (หลังทดสอบกับเครื่องจริง 583-02/PT280)
1.3 เดลิเวอรี + push แจ้งเตือนออเดอร์ (APNs, เสียงยาว ≤30 วินาที)
1.4+ โต๊ะ/QR Order, โมดูลจัดการร้าน และงาน 8 ข้อที่ยกมาจาก Android

7. ความเสี่ยงและสิ่งที่ยังไม่รู้

  • พิมพ์ WiFi 0.9.0 ยังไม่ผ่านการทดสอบบนเครื่องจริง ถ้าทดสอบไม่ผ่านก่อนส่ง แนะนำให้ปิดไว้ก่อน แล้วไปเปิดในรุ่น 1.1
  • ยังไม่รู้เลข build ล่าสุดใน App Store Connect และบัญชีนี้เคยถูกปฏิเสธหรือไม่
  • backend ของ 0.9.0 (PR#118) ยังเป็น draft ต้องยืนยันว่า API ที่ 1.0.0 ใช้อยู่บน prod ครบแล้ว
  • App Review อาจถามว่า "ร้านค้าสมัครที่ไหน" ต้องตอบในโน้ตว่าสมัครผ่านเว็บและใช้แบบ B2B

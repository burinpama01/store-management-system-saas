Task 1 — Release preparation

  • โหลด VERCEL_TOKEN จาก .env.local เฉพาะใน environment ของ Vercel CLI โดยไม่แสดงค่า
  • ยืนยันว่า .env.local ถูก Git ignore และ linked project ถูกต้อง
  • bump patch version จาก 0.31.0 เป็น 0.31.1 ใน package.json และ package-lock.json

Task 2 — Verification gates

  • รัน npm test, npm run typecheck, npm run lint และ npm run build
  • รัน git diff --check และตรวจว่าไม่มี secret หรือไฟล์นอก scope ถูก stage
  • ส่ง final diff ให้ code_reviewer แบบ review-only; blocker ต้องแก้และ verify ใหม่

Task 3 — Commit and production deploy

  • stage เฉพาะ source, regression tests, version files และ HTML artifacts ของงานนี้
  • commit message ต้องระบุเวอร์ชัน 0.31.1
  • deploy ด้วย vercel --prod --yes โดย inject token ผ่าน process environment
  • เก็บ production URL และตรวจ HTTP response/smoke โดยไม่แก้ข้อมูลร้าน

Safety / rollback

  • ไม่มี schema migration, environment write หรือ customer data mutation
  • ห้าม stage .env.local, attachment/temp/marketing/artifacts หรือไฟล์ผู้ใช้นอก scope
  • หาก deploy fail ให้คง commit ไว้และรายงาน URL/error; rollback production ใช้ Vercel previous deployment หลังได้รับอนุญาตเพิ่มเติม

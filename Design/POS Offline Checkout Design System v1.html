Design System v1 · ภาพจำลอง ไม่ใช่ระบบจริง

รับเงินแล้ว ≠ ซิงก์แล้ว

หน้าจอต้องบอกสถานะเงิน สถานะข้อมูล และสถานะเครื่องพิมพ์แยกกัน พร้อมทางแก้ที่ไม่ทำให้แคชเชียร์รับเงินซ้ำ

ตัวเลข/สินค้า/เลขอ้างอิงทั้งหมดเป็นข้อมูลตัวอย่าง ไม่มีการรับเงินหรือบันทึกธุรกรรมจากหน้านี้

04 · จุดที่ต้องมีทางกู้คืน

รับเงินแล้วแต่เก็บข้อมูลไม่สำเร็จ

แสดง error ใกล้ปุ่มยืนยัน คงตะกร้าและ saleId พร้อมข้อความ “ห้ามรับเงินซ้ำ” ให้จดหลักฐานฉุกเฉินและติดต่อหัวหน้า ไม่ล้างจอหรือเสนอให้เริ่มบิลใหม่

เน็ตกลับ แต่ login หมดอายุ

แจ้ง “บิลยังอยู่ในเครื่อง กรุณาเข้าใช้งานอีกครั้งเพื่อซิงก์” หลัง login ต้องตรวจสาขา/บัญชีเดิม ห้ามโยกข้อมูลไปสาขาใหม่

iPad ต่อ Print Hub แต่ WAN หลุด

แสดง “รับเงินแล้ว · รอพิมพ์” ไม่แสดงว่า Hub พิมพ์สำเร็จ งาน cloud-only รอออนไลน์หรือใช้ transport ออฟไลน์ที่ผ่านการทดสอบจริง

ออกจากระบบหรือปิดกะทั้งที่มีบิลค้าง

แสดงจำนวนและยอด pending แยกจากยอดส่วนกลาง ให้ตรวจรายการค้างก่อนปิดกะ; logout ล็อกข้อมูลแต่ไม่ลบทิ้ง ปุ่มล้างข้อมูลไม่อยู่ใน flow ปกติ

05 · Tokens และกฎหน้าจอ

ความหมายสี / พฤติกรรม

จอและ interactionมือถือ <768px เรียงแนวตั้ง; tablet ≥768px catalog+cart; ปุ่มอย่างน้อย 44px, focus-visible, status ประกาศผ่าน aria-live ใน runtime โดยไม่ย้าย focus ทุกครั้งที่เน็ตเปลี่ยน

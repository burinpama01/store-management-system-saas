ทำไมต้องเขียนหน่วยเสียงเอง

Windows ไม่มีชุดรู้จำเสียงภาษาไทยเลย (วัดแล้วทั้ง System.Speech และ OneCore/WinRT รองรับแค่ en-US/en-GB) คำปลุกภาษาไทยจึงต้องอธิบายให้ engine ภาษาอังกฤษฟังสองทางพร้อมกันในไวยากรณ์เดียว:

  1. รูปสะกดอังกฤษ เช่น sa wat dee oh es — ให้ engine ใช้พจนานุกรมของตัวเอง ทนสำเนียงต่างคนได้ดีกว่า
  2. หน่วยเสียง SAPI — บังคับเสียงตรง ๆ สำหรับคำที่สะกดอังกฤษแล้วเพี้ยน
กับดักที่เสียเวลาไปแล้วหนึ่งรอบ: ต้องตั้ง SrgsDocument.PhoneticAlphabet = Sapi ไม่งั้น System.Speech จะตีความเป็นชุด UPS แล้วโยน Invalid phoneme ' ' ทั้งไวยากรณ์ — พังทั้งฟีเจอร์โดยไม่มี error ให้ผู้ใช้เห็น จึงต้องมี unit test ยืนยันว่าไวยากรณ์โหลดขึ้นจริง

2. คำล่อ (decoy) — วิธีลดการปลุกผิดโดยไม่ต้องขันเกณฑ์

ก่อนใส่คำล่อ ประโยค “หวัดดีครับพี่” ถูกจับเป็น watdee_os ที่ความมั่นใจ 0.84 — สูงกว่าเกณฑ์ปลุก แปลว่าทักทายเพื่อนร่วมงานทีไร POS ตื่นทุกที

วิธีแก้ที่ใช้: โหลดไวยากรณ์คู่แข่งที่มีคำทักทายเหล่านั้นอยู่ (wat dee krap, sa wat dee ka, ha lo, oh kay krap …) เมื่อ engine มี “ที่ให้เสียงลง” ที่ตรงกว่า มันจะไม่ถูกบีบให้เลือกคำปลุกที่ใกล้ที่สุด

ผลหลังใส่คำล่อ: false wake 1/10 → 0/10 โดยที่คำปลุกจริงยังจับได้เท่าเดิม (ถ้าแก้ด้วยการดันเกณฑ์ความมั่นใจแทน คำปลุกไทยจะหลุดทันทีเพราะบางคำอยู่ที่ 0.70)

4. สัญญาข้อความและการส่งไมค์

native ฟังคำปลุก→ ปล่อยไมค์ + รอ RecognizeCompleted→ wake.detected→ เว็บเปิดไมค์→ command.sessionStarted→ คุยต่อ = sessionExtended→ sessionEnded คืนไมค์
ข้อความทิศทางความหมายและกฎ
wake.detectednative → webได้ยินคำปลุกและปล่อยไมค์แล้ว — ส่งได้แค่ phraseId กับ confidence ห้ามมี transcript/intent/เสียง
wake.fallbacknative → webปลุกแล้วแต่ไปต่อไม่ได้ ให้เว็บโชว์ “แตะเพื่อพูด”
command.sessionStartedweb → nativeเว็บถือไมค์แล้ว เริ่มนับ watchdog
command.sessionExtendedweb → nativeยังคุยต่อ (multi-turn) ขอต่อเวลา
command.sessionEndedweb → nativeจบรอบ คืนไมค์ให้ native

ขอบเขตความปลอดภัย (บังคับด้วยเทสต์ ไม่ใช่แค่เขียนไว้)

  • ข้อความจาก native คือ ข้อมูล ไม่ใช่คำสั่ง — ฟิลด์แปลกปลอม (intent, transcript, command) ถูกตัดทิ้งตั้งแต่ชั้น parse
  • wake หนึ่งครั้ง = สิทธิ์เปิดไมค์หนึ่งรอบ ไม่ใช่สิทธิ์ทำรายการ การตีความยังเป็นของโมดูลเดิมบนเว็บทั้งหมด
  • seq ย้อนหลังหรือซ้ำถูกทิ้ง; phraseId ที่ไม่อยู่ในชุดห้าคำถูกปฏิเสธ
  • ห้ามสร้างคลิกปลอมเพื่อข้าม user-activation ของเบราว์เซอร์ — ถ้าเปิดไมค์เองไม่ได้ ต้องให้ผู้ใช้แตะ

5. Watchdog — กันไมค์ค้างแบบเงียบ

ถ้าเว็บเปิด session แล้วแท็บถูกปิด เครื่องล็อก หรือเบราว์เซอร์ปฏิเสธเงียบ ๆ native จะรอไมค์คืนตลอดกาล = คำปลุกตายทั้งเครื่องโดยไม่มี error ให้เห็น

ตัวจับเวลาค่าเหตุผลของค่านี้
รอเว็บตอบว่าเริ่มฟัง1,200 msงบของแผน v1 คือ wake→listening p95 ≤900ms; เกินกว่านี้ถือว่า user-activation ไม่ผ่าน
หน้าต่างฟังของเว็บ (ของจริง)6,000 msแผนเขียน 2s แต่วัดใช้งานจริงได้ 1.8–3.8s จึงตั้ง 6s
watchdog ต่อรอบ9,000 msต้องมากกว่า 6,000 เสมอ ไม่งั้นตัดกลางประโยคผู้ใช้ — บังคับด้วย guard ใน constructor และมีเทสต์คุม
เพดานรวม multi-turn20,000 msTest Matrix ของแผนกำหนดเคส multi-turn 15 วินาทีต้องผ่าน
หมดเวลาแล้วต้อง คืนไมค์ให้ native ทันที และตกไปที่ push-to-talk เสมอ ห้ามเงียบ

6. สิ่งที่ยังไม่ยืนยัน

ตัวเลขทั้งหมดในเอกสารนี้มาจากเสียงสังเคราะห์ (Microsoft Pattara th-TH / David, George en) บนเครื่องเงียบ ไม่มีเสียงร้าน ไม่มีสำเนียงหลากหลาย ไม่มีระยะห่างจากไมค์ — จึงเป็น เพดานบน ไม่ใช่ตัวเลขที่ร้านจะเจอ
ข้อที่ต้องพิสูจน์บนเครื่องร้าน: recall กับคนพูดจริงในเสียง 65–75 dBA, false wake ต่อกะ, CPU ตอน standby, และการส่งไมค์กับเบราว์เซอร์จริง (ไม่ใช่ engine ตัวที่สองที่ใช้จำลอง)

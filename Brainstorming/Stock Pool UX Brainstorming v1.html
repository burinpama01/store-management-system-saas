Stock Pool UX Brainstorming v1

ลดการสลับหน้าและรองรับสินค้าหลายรายการที่ใช้สต๊อกก้อนเดียวกัน

ปัญหาปัจจุบัน

1. สร้างสินค้ายังใส่สต๊อกไม่ได้
2. สร้างคลัง Variantต้องออกไปอีกเครื่องมือ
3. ผูก Variantกลับมาแก้สินค้าอีกครั้ง
4. ปรับสต๊อกเปลี่ยนไปหน้าสต๊อก

แนวทางที่พิจารณา

แนะนำ

A. Stock Pool กลาง

สร้างยอดกลางแยกจากสินค้า แต่ละ Variant ผูกได้หนึ่ง Pool และกำหนดจำนวนที่ตัดต่อการขาย

  • แชร์ข้ามสินค้าได้จริง
  • ตัด/คืนสต๊อกแม่นยำ
  • ขยายเป็น audit ledger ได้

B. ใช้ Variant หนึ่งตัวเป็นแม่

ให้ Variant อื่นอ้างยอดจาก Variant หลัก

  • แก้ฐานข้อมูลน้อยกว่า
  • ชื่อและ ownership สับสน
  • ลบตัวแม่แล้วความสัมพันธ์เปราะ

C. Sync ยอดระหว่าง Variant

คัดลอกยอดไปยังทุกรายการที่ใช้ร่วมกัน

  • ทำ UI ได้เร็ว
  • เสี่ยงยอดไม่ตรงเมื่อขายพร้อมกัน
  • ไม่เหมาะกับ production

Stock Pool คืออะไร

Stock Pool คือยอดวัตถุดิบหรือหน่วยสินค้าจริงที่เก็บอยู่ เช่น เบียร์สิงห์ขวด มี 30 ขวด สินค้าหน้าร้านหลายรายการสามารถอ้างยอดนี้ได้ แต่แต่ละ Variant ผูกกับ Pool ได้เพียงหนึ่งรายการ

เพิ่มสต๊อกสินค้า

1. ค้นหาและเลือกสินค้าจากเมนูสินค้า

2. หากไม่มี Variant ระบบเปิดส่วน “สร้าง Variant” ใน Dialog นี้ทันทีและบังคับสร้างก่อนดำเนินการต่อ

3. เลือก “สร้าง Stock Pool ใหม่” หรือ “ใช้ Stock Pool ร่วมที่มีอยู่” แล้วกำหนดจำนวนที่ตัดต่อการขาย

แทนที่ยอดเดิมหลังตรวจนับ เช่น 30 → 27

กติกาหลักที่เสนอ

  • Variant หนึ่งตัวผูกกับ Stock Pool ได้สูงสุดหนึ่ง Pool
  • Pool เดียวถูกใช้โดย Variant จากสินค้าคนละรายการได้
  • ยอดที่ตัด = จำนวนที่ขาย × จำนวนหน่วยที่ Variant ใช้
  • ยกเลิกหรือ void คืนยอดเข้าที่ Pool เดิมด้วยจำนวนเดียวกัน
  • หากสต๊อกไม่พอ ระบบไม่อนุญาตให้ขายจนยอดติดลบ
  • “รับเข้า” เพิ่มยอด ส่วน “กำหนดยอดใหม่” แทนที่ยอดและควรบังคับระบุเหตุผล

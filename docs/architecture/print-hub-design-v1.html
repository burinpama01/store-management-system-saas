StoreOS Print Hub — เอกสารออกแบบ v1

เป้าหมาย: ให้ร้านที่ใช้ POS บน tablet/iPad สั่งพิมพ์ใบเสร็จผ่าน Print Hub กลาง บนเครื่อง Windows (มินิพีซี/เครื่องแคชเชียร์) โดยไม่ต้องให้ผู้ใช้รัน npm run print:bridge เอง และ Hub เปิดเอง/ตรวจสถานะเองได้

1. ปัญหา & ข้อจำกัดทางเทคนิค

วันนี้ระบบมี scripts/print-bridge.mjs = HTTP server ที่ 127.0.0.1:17878 รับ /print แล้ว forward ESC/POS bytes ไป TCP printer ทำงานได้บนเครื่องแคชเชียร์ที่เปิด bridge เอง แต่:

  • เปิดด้วย npm run print:bridge = dev-oriented, non-dev ทำไม่เป็น, ไม่ auto-start, ไม่มี status
  • bridge bind เฉพาะ 127.0.0.1 → tablet/iPad เครื่องอื่นใน LAN เข้าไม่ถึง

ข้อจำกัดหัวใจ POS production เสิร์ฟผ่าน HTTPS (store-os-manage.vercel.app) แต่ bridge เป็น HTTP:

  • กรณี 127.0.0.1 เบราว์เซอร์ยกเว้นให้ (localhost = potentially-trustworthy) → เครื่องแคชเชียร์ที่เปิด POS บนเครื่องตัวเองพิมพ์ได้
  • กรณี iPad ยิงข้าม LAN ไป http://192.168.x.x:17878 = Mixed-Content Block โดน Safari/Chrome บล็อกถาวร ไม่มีปุ่ม override บน iOS

2. ทางเลือก transport (จุดตัดสินสถาปัตยกรรม)

ตัวเลือก A — Direct LAN fetch (tablet → Hub)

iPad ยิง fetch("http://192.168.x.x:17878/print") ตรงไป Hub

ต้องแก้ mixed-content ด้วยวิธีใดวิธีหนึ่ง:

  • ติดตั้ง trusted cert ของ hostname บน Hub + ลง CA cert ในทุก iPad → setup โหดมากต่อร้าน
  • หรือใช้ public DNS ชี้ private IP + Let's Encrypt (DNS-01) แล้วฝัง private key ลง Hub → เสี่ยงความปลอดภัย + IP ต่อร้านไม่เท่ากัน

สรุป: ทำได้แต่เปราะ ต้องตั้งค่าต่อเครื่อง ดูแลยาก ไม่เหมาะ non-dev

ตัวเลือก C — Cloud relay / print queue แนะนำ

มาตรฐานเดียวกับ Star CloudPRNT / Epson Server-Direct-Print

tablet/iPad (HTTPS) ──enqueue──▶ StoreOS server (queue) ▲ │ long-poll + claim (HTTPS, server-to-server) │ Print Hub (cashier PC) ──TCP 9100──▶ printer
  • เบราว์เซอร์ยิงเฉพาะ HTTPS → server → ไม่มี mixed-content เลย
  • Hub poll งานจาก server (ขาออกจาก LAN) → ไม่ต้องเปิด port เข้า LAN, ไม่ต้อง cert
  • iPad กี่เครื่องก็ได้ ทุกเครื่อง enqueue งานไปคิวเดียว Hub ดึงไปพิมพ์
  • ได้ของแถม: retry, สถานะงาน (pending/printed/failed), heartbeat รู้ว่า Hub online ไหม

แลกกับ: ต้องเพิ่ม print queue ฝั่ง server (1 ตาราง + 3 endpoint) และ hub token ต่อร้าน

คำแนะนำของผม: ใช้ ตัวเลือก C เพราะมัน ตอบโจทย์ "แต่ละ tablet พิมพ์ผ่าน Hub" ได้ตรงกว่า และเลี่ยง mixed-content ทั้งหมดโดยไม่ต้องยุ่งกับ cert บน iPad ส่วน path เดิม (POS บนเครื่องแคชเชียร์ → 127.0.0.1 bridge) ยังเก็บไว้ทำงานคู่กันได้ (fast path เมื่อเปิดบนเครื่องเดียวกัน)

3. Data model (Supabase migration)

ตาราง print_jobs (คิวงานพิมพ์)

id            uuid pk
organization_id uuid
store_id      uuid            -- scope ต่อร้าน
printer_id    uuid null       -- เครื่องเป้าหมาย (หรือ default)
target_host   text            -- IP printer (validate private LAN)
target_port   int default 9100
payload_b64   text            -- ESC/POS raster bytes, base64 (≤256KB)
status        text            -- 'pending' | 'claimed' | 'printed' | 'failed'
claimed_at    timestamptz null
printed_at    timestamptz null
error         text null
attempts      int default 0
created_at    timestamptz default now()

เพิ่มใน stores (หรือ store_print_hubs)

print_hub_token       text   -- secret ต่อร้าน, Hub ใช้ auth (เก็บแบบ hash)
print_hub_last_seen   timestamptz  -- heartbeat ล่าสุด → ใช้โชว์ online/offline

RLS: enqueue ผ่าน server action (มี store context อยู่แล้ว); poll/claim/ack ใช้ service client + ตรวจ print_hub_token เท่านั้น (Hub ไม่มี user session)

4. Endpoints

Routeผู้เรียกหน้าที่
POST /api/print/enqueuePOS (tablet, HTTPS)สร้างงานพิมพ์ลงคิว (auth = user session + store)
POST /api/print/hub/pollPrint Hubclaim งาน pending ของร้าน (auth = hub token) + อัปเดต last_seen
POST /api/print/hub/ackPrint Hubรายงานผล printed/failed (+error)
GET /api/print/hub/statusSettings UIคืน last_seen + จำนวนงานค้าง → โชว์สถานะ Hub

5. Print Hub agent (แทน print-bridge เดิม)

scripts/print-hub.mjs — long-poll loop:

loop:
  POST /api/print/hub/poll  {storeId, hubToken}
    → job? → ส่ง payload ทาง TCP ไป target_host:target_port
           → POST /api/print/hub/ack {jobId, ok|error}
    → ว่าง → backoff sleep แล้ว poll ต่อ
  ส่ง heartbeat ทุก poll (last_seen)

config อ่านจาก print-hub.config.json (ข้าง exe): { serverUrl, storeId, hubToken, pollIntervalMs }

เก็บ bridge เดิม (loopback) ไว้สำหรับ fast path เครื่องแคชเชียร์ ใช้โค้ด TCP-send ร่วมกัน

6. Installer + auto-start (Windows)

  • scripts/print-hub/install-windows.ps1 — สร้าง config, ลง Task Scheduler "at logon", start ทันที
  • scripts/print-hub/uninstall-windows.ps1 — ลบ task + config
  • scripts/print-hub/print-hub.cmd — launcher เรียก node print-hub.mjs (ซ่อนหน้าต่าง)
  • scripts/print-hub/README-TH.txt — คู่มือ 3 ขั้นตอนสำหรับเจ้าของร้าน

ใช้ Task Scheduler (มากับ Windows) → auto-start ตอน logon, restart เมื่อ crash; ไม่ต้องลง toolchain เพิ่ม นอกจาก Node runtime (จะแถม note ดาวน์โหลด Node LTS หรือ bundle node.exe ภายหลัง)

7. Settings UI — หน้า "Print Hub" (/settings/print-hub)

  • สถานะ Hub: 🟢 online / 🔴 offline (จาก last_seen heartbeat) + งานค้างในคิว
  • Hub token: ปุ่มสร้าง/หมุน token + คัดลอก (ใส่ใน config ของ Hub)
  • ดาวน์โหลดตัวติดตั้ง: ลิงก์ installer + คู่มือภาษาไทย
  • ทดสอบพิมพ์: ปุ่ม enqueue ใบทดสอบ → ดูว่า Hub ดึงไปออกจริง
  • คำอธิบาย: "iPad/tablet ใช้ POS ได้เลย งานพิมพ์ส่งผ่าน Print Hub กลางบนเครื่องแคชเชียร์อัตโนมัติ"

9. ความปลอดภัย

  • hub token เก็บแบบ hash, เทียบ constant-time, หมุนได้จาก UI
  • enqueue ตรวจ store membership + feature gate (เครื่องพิมพ์/Enterprise ตามแพ็กเกจ)
  • validate target_host เป็น private LAN เท่านั้น (เหมือน bridge เดิม) ป้องกัน SSRF
  • จำกัด payload ≤256KB, จำกัด attempts, หมดอายุงานเก่าในคิว
  • poll/ack ไม่คืนข้อมูลร้านอื่น (scope ด้วย storeId+token)
